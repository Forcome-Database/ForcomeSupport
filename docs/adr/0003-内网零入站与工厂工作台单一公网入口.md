# 内网零入站，工厂工作台是唯一公网入口；境内直连、境外经固定代理

生产系统部署在中国大陆的公司服务器上，网络拓扑定为（2026-09-24 用户同意）：

- **出站按目的地分流**：积加、钉钉、易仓从公司固定 IP 直连，积加 IP 白名单登记这个 IP；Google（Gmail）、Shopify、亚马逊 SP-API、17TRACK 等境外服务，经公司已有的固定境外代理出去。系统只配置一个代理地址，按域名分流在代理侧由运维维护，我们提供放行域名清单。
- **外部系统零入站**：Gmail（Pub/Sub pull + `history.list` 轮询）、钉钉通讯录（Stream 长连接）、Shopify（轮询）、17TRACK（轮询）、SP-API feed 处理报告（轮询），全部由系统主动连出，不对外部系统开放任何回调地址。
- **唯一公网入口**：公司固定 IP 上的一个子域名，HTTPS，证书用 Let's Encrypt（DNS 验证）自动续期；反向代理只放行工厂工作台与钉钉免登路径，并限制访问频率。其余页面只在内网可达。

## Considered Options

- 各集成使用 Webhook 或 HTTP 推送：时效更好，但每个回调都要一个公网地址，暴露面大；而这些业务本来就是异步的（feed 最长约 8 小时，轨迹每 4 小时轮询），分钟级延迟可以接受。
- 工厂人员用 VPN 或零信任网关：钉钉内打开的 H5 页面装不了 VPN 客户端，零信任对钉钉 H5 的兼容性和运维成本都偏高。
- 所有外部调用统一走境外代理：积加、钉钉是境内服务，绕境外反而更慢、更不稳定。

## Consequences

- 新接一个外部服务时，优先选能主动拉取或长连接的方式；确实必须接收推送的，要单独评估，不能默认开入站。
- 公网入口是唯一的攻击面：路径白名单、钉钉免登、角色限定为工厂人员，三者缺一不可。
- 钉钉 Stream 能否经 HTTP 代理连通需联调验证；按分流规则钉钉直连，不经代理。
- 依据见 `research/gmail-shopify-dingtalk`、`research/tracking-source`、`research/sp-api` 分支的调研报告。

## 修订（2026-09-24，交叉审查复核，见 `.scratch/tech-plan/reviews/复核结论.md`）

- **出站实现**：系统设置 `HTTPS_PROXY` 指向固定境外代理，并以 `NO_PROXY` 列出积加、钉钉、易仓等境内域名，境内流量不经代理进程；代理故障时钉钉告警通道不受影响。api 与 worker 都会出站（钉钉登录换取身份、17TRACK 即时查询），两者使用同一套代理配置。
- **内网 HTTPS**：第一期就需要内网域名（公司域名下的子域名，内网 DNS 解析）与受信证书：会话 Cookie 为 `Secure`，钉钉扫码登录与钉钉内免登都要求 HTTPS。caddy 用 DNS-01 申请 Let's Encrypt 证书，不需要入站。公网入口仍到第二期才开。

## 修订（2026-10-04，待办 03 落地；按用户 2026-10-04 口径）

- **内网 HTTPS 先用 caddy 内部 CA**：公司域名与 DNS 服务商的 API 令牌到位前，caddy 用 `tls internal` 签发证书。根证书（10 年）与私钥存在 `caddy_data` 卷，部署脚本导出根证书并只用它核对证书链与域名，员工浏览器安装这张根证书（`docs/部署说明.md`）；会话 Cookie 照样是 `Secure`。到位后切到 DNS-01：用 xcaddy 编进 DNS 服务商插件，Caddyfile 加 `tls_dns` 片段并把 `TLS_MODE` 改为 `dns`，部署脚本的 HTTPS 核对与冒烟改用系统证书库。Caddyfile 不设 `trusted_proxies`，`X-Forwarded-For` 由 caddy 用真实客户端地址改写（ADR 0010 修订）。
- **出站代理可配置、暂未实测**：现在没有可用代理。`HTTPS_PROXY`、`HTTP_PROXY`、`NO_PROXY` 写在环境文件，Compose 以大小写两种写法传给 api 与 worker（undici 优先读小写，Docker 客户端配置了代理时会注入小写变量）；`loadConfig` 启动时校验代理地址格式。`NO_PROXY` 默认 `localhost,127.0.0.1,postgres,api,caddy,.dingtalk.com`，域名写成带前导点的形式（undici、curl、Go 都按子域名匹配）。放行域名、`NO_PROXY` 与内网 DNS 清单见 `docs/部署说明.md` 第 6 节。

## 修订（2026-10-06，待办 05 落地）

- **钉钉 Stream 经同一个出站连接**：通讯录事件的 Stream 长连接用 undici 的 WebSocket，传入进程共用的 `EnvHttpProxyAgent`（`integration/http.ts` 的 `outboundDispatcher`），与 HTTP 调用读同一组代理变量、同样遵守 `NO_PROXY`（默认 `.dingtalk.com` 直连）。没用钉钉官方的 Node SDK `dingtalk-stream`：它的 WebSocket（ws）不读代理变量，另见 ADR 0009 修订。
- **扫码登录不需要入站**：钉钉开放平台的「重定向 URL」填本系统的内网地址 `https://<内网域名>[:端口]/login/dingtalk`。扫码确认后是员工浏览器跳转过来，钉钉服务器不访问它；员工浏览器另要能直接访问 `login.dingtalk.com` 与 `g.alicdn.com`（钉钉的扫码登录框）。内部 CA 的证书要先装进员工浏览器（`docs/部署说明.md` 第 4、11 节）。
