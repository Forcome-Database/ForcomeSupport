# 不设个人信息脱敏与留存限制，按最佳体验设计

北美买家的个人信息（姓名、邮箱、电话、地址、来信原文）在生产系统中不脱敏、不到期删除；工单、邮件原文、审计全部长期保留；审计记录完整的前后值；发给模型的来信用原文，不做占位符替换（2026-09-24 用户决定：不考虑合规问题，按最佳体验去做）。

## Considered Options

- 按亚马逊数据保护政策，订单交付后 30 天把个人信息替换为占位符、删除邮件原文，审计只记「已修改」：代价是坐席和模型看不到历史上下文，还要维护定时脱敏任务和一条占位符还原链路。
- 加密归档、到期销毁密钥（加密擦除）：复杂度同上。
- 先请法务出意见再定：时间不可控，会挡住技术方案。

## Consequences

- CCPA、墨西哥 LFPDPPP、中国个人信息出境规则、亚马逊 DPP 的留存要求，都不作为设计约束，相应风险由业务自担。
- 以后如果要补合规，需要新增字段级脱敏任务、审计值的清洗，以及模型调用前的脱敏层。数据已经长期留存，补救成本会随时间上升。
- 订单改由平台直读（ADR 0011），只用 SP-API 非受限角色，不申请买家个人信息受限角色；这一点与本决策无关。
