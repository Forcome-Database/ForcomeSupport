# 服务端会话，角色固定在代码里，店铺范围与生产厂隔离在应用层强制（不用 RLS）

身份与权限的实现（2026-09-24 用户同意）：

- **会话**：服务端会话存在 PostgreSQL，浏览器只持有 httpOnly、Secure 的 Cookie；无操作 7 天过期，有操作自动续期。钉钉扫码登录与钉钉内免登都换出同一种会话。主应用与工厂工作台的 Cookie 各自独立。
- **同步与停用**（D-16）：钉钉 Stream 变更事件实时同步，外加每小时全量对账。成员停用时，立即失效会话、释放他持有的锁；他负责的工单与售后单转入「待分配」并通知客服主管；他是备用审批人时提醒管理员重新指定。
- **角色**：6 个角色固定在代码里；PRD 10.1 能力矩阵是 `packages/contracts` 中的常量，前端据此显示，后端据此强制；一个成员可有多个角色，权限取并集。「只能看自己发起或负责的」由能力校验加归属校验完成。
- **店铺范围**（R-ST-06）：各模块的仓储查询必须接收带授权店铺列表的上下文参数（缺了编译不过），并由测试覆盖越权场景。
- **生产厂隔离**（R-FT-02）：工厂接口集中在 `/api/factory/*`，使用只含必要字段的输出结构；生产厂 ID 只从会话取；客户姓名、地址、电话只在寄件任务中出现，寄件完成 30 天后对生产厂隐藏（只限制可见性，不删除数据）。
- **审计**：服务层在写事务内记录，系统操作记为「系统」；登录、登出、强制接手、导出也记录；只读查询不记。客服主管与管理员可查全部，其他角色只看自己的。
- **钉钉通知**：每条通知带对象编号与时间，避免被「同内容一天一条」静默吞掉；同一人的提醒 5 分钟内合并发送；统计每月调用量，接近配额时告警。

## Considered Options

- JWT：无状态，但停用成员后无法立即踢下线。
- PostgreSQL 行级安全（RLS）作第二道防线：每个连接要设置会话变量，和连接池、Drizzle、pg-boss worker 配合容易出错、难调试；按现在的规模，应用层强制加测试已经足够。
- 角色可在界面自定义：PRD 的角色与能力是固定的，自定义角色只会增加测试面。

## Consequences

- 新增的查询只要漏掉范围参数就无法编译；但原生 SQL 与报表查询（`report` 只读角色）需要在评审和测试中单独检查范围过滤。
- 集团钉钉的版本待确认；如果是标准版，配额会限制通知量，需要持续监控。
