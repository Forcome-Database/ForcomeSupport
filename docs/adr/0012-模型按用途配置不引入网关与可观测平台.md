# 模型按 11 个用途配置、在应用层切换；不引入 LiteLLM、Langfuse 与专用向量库

在 ADR 0001（Vercel AI SDK）之上，模型接入层定为（2026-09-24 用户同意）：

- **按用途调用**：业务代码只能按用途调用，不能直接写模型名。用途 11 个：`triage`（风险、意图、情绪、语言、紧急度、注入嫌疑一次完成）、`draft`、`check`、`translate`、`summarize`、`extract`、`assess`（售后责任与处理方式建议，含看图）、`knowledge`（缺口聚类、沉淀起草、文档解析）、`judge`（评测打分）、`embed`、`rerank`。每个用途配置主模型、备用模型、推理强度、输出上限、时限、提示词版本、模式版本。
- **配置**：数据库里存「用途 → 模型与参数」，变更后用 AI SDK `customProvider` 重建；设置里新增只有管理员能用的「模型」页，只能切换主备模型、调整时限，改动记入审计。
- **时限与熔断**：60 秒总时限只管 `triage` + `draft`（E-03），其他用途各设时限；熔断按「用途 × 模型」统计，达到阈值改用备用模型，备用模型也失败时同步用途直接走 E-03 降级。NewAPI 负责渠道之间的切换，应用层负责模型之间的切换。
- **调用记录**：AI SDK 7 遥测写入自有表，字段包括用途、提供方、模型、提示词与模式版本、上下文清单（知识条目与版本、订单快照哈希）、四项用量（拿不到记 null）、成本、耗时、首字耗时、停止原因、结构化校验结果、降级路径、关联对象，以及完整的请求与响应；长期保留（ADR 0004）。这张表同时是评测样本和成本报表的数据源。
- **提示词分两层**：系统提示词、输出模式（`packages/contracts/ai/` 的 zod 模式）、评分细则放在代码仓库，经评审和回归评测后发布；意图流程说明、语气、店铺政策口径等业务内容存在数据库或知识库，由客服主管维护，带版本。
- **组件**：向量检索用 pgvector（PostgreSQL 18 扩展）；离线评测用自写脚本（vitest），Promptfoo 备选。
- **落地节奏**：第二期上线接入层、调用记录表、评测脚本骨架，以及 `translate`、`summarize`、`assess`、`extract`；第三期上线其余 7 个用途，上线前建好回归集。

## Considered Options

- LiteLLM、Portkey、OpenRouter 作网关：与 NewAPI 功能重叠；LiteLLM 需要额外的 PostgreSQL 与 Redis，Portkey 开源版缺日志与成本分析，OpenRouter 只有托管版并收手续费。
- Langfuse 自托管：要额外部署 ClickHouse、Redis 与对象存储，官方说 Docker Compose 方式只适合测试；自有表已能满足需求。
- Braintrust：自托管只有企业版，并依赖 SaaS 控制面。
- 专用向量库（Qdrant、Milvus）：知识量小，pgvector 足够。
- 只设 5 个用途：`assess`、`extract` 在第二期就需要，`judge`、`embed` 需要与在线用途分开配置。

## Consequences

- 换模型或厂商只改配置，不改业务代码；但每次切换都应先跑回归评测。
- 「模型」页是 PRD 新增的内容，需要回写。
- NewAPI 能否提供嵌入与重排渠道、能否透传批处理，需实测（`research/llm-uses` U-07、U-08）。
- 依据见 `research/llm-compat`、`research/llm-uses` 分支的调研报告。

## 修订（2026-10-03，文档漂移审查）

- 用途以 PRD 11.3 与 P25 为准，共 10 个；`rerank` 是否需要，待第三期规格依据样本再定。
- P25 可编辑项以 PRD P25 为准：主模型、备用模型、推理强度、输出上限、时限、提示词版本、模式版本（不只主备与时限）。
- 后果中「『模型』页是 PRD 新增的内容，需要回写」已由 PRD v2.8（D-21）完成，P25 于 v2.11 出图。
