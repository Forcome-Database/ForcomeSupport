# 前端用 Vite + React 单页应用，工厂工作台是同一项目里的独立构建入口

在已定的 shadcn/ui + Tailwind CSS v4（PRD D-10）之上，前端工程定为（2026-09-24 用户同意）：

- **框架**：Vite + React 19 单页应用，构建成静态文件，由 caddy 托管；不用 Next.js。
- **路由**：TanStack Router；查询参数经 zod 校验，筛选条件放在 URL 里，支撑 PRD 中「带筛选跳转到 P04 / P13」。
- **数据与组件**：TanStack Query（收到 SSE 的变化通知时让对应缓存失效）；TanStack Table + shadcn Data Table；react-hook-form + `packages/contracts` 的 zod 模式；shadcn Charts（Recharts）。客户端全局状态确有需要时用 Zustand。
- **设计令牌**：用一次性脚本把 `design/spec/ui.py` 的 `T` 转成 `globals.css`（shadcn 变量 + `@theme` 语义色），此后以 `globals.css` 为准；原型改令牌时同步修改两边。
- **密度**：`<html data-density>` 切换两套 CSS 变量；用户选择存在服务端的成员偏好里。
- **工厂工作台**：同一个 `apps/web` 项目、两个构建入口（`index.html`、`factory.html`），共享组件与令牌。公网入口只放行工厂入口的静态资源、`/api/factory/*` 和钉钉免登接口。主应用只支持桌面（≥ 1280px）；工厂工作台做响应式，以手机为主。
- **语言**：界面只做中文，文案直接写在组件里，不引入 i18n 框架。
- **测试**：Vitest + Testing Library；Playwright 端到端测试覆盖 PRD 第 13 节验收标准；视觉对照原型人工验收，不做像素级截图比对。

## Considered Options

- Next.js：多一个 Node 服务端进程；服务端渲染和 SEO 对内部系统没有价值。
- 工厂工作台与主应用打在同一个包里、只靠路由区分：外网虽然访问不了主应用的接口，但能下载到主应用的全部前端代码和接口路径。
- 单独建 `apps/factory`：组件和令牌要跨包共享，工程成本更高，却没有额外收益。
- 长期从 `ui.py` 生成令牌：会让生产代码依赖 Python 原型。

## Consequences

- 工厂接口必须集中在 `/api/factory/*` 前缀下，由后端再按「工厂人员 + 所属生产厂」鉴权；caddy 的路径白名单只是第一道防线。
- 原型与 `globals.css` 两份令牌并存，改令牌时需要人工同步。

## 修订（2026-10-04，待办 02 落地）

- **组件库**：Tailwind CSS v4（`@tailwindcss/vite`）+ shadcn/ui（`apps/web/components.json`：radix 基础、`radix-nova` 样式，组件在 `src/components/ui`，路径别名 `@/`）。CLI 生成的组件默认样式不直接用：先按设计规范板改到原型的尺寸、字号、圆角、阴影与交互态（已改 Button、Card、Avatar，按钮 28 / 32 / 36、字号 12 / 13 / 14、圆角 8、焦点环 ring-2 + offset-2），其余组件第一次用到时同样处理，组件里不留未核对过的变体。
- **设计令牌**：`apps/web/src/styles/globals.css`，照设计规范板第 12 节的令牌对照与 `globals.css` 摘要写成；`ui.T` 里其余的键按同一命名规则补齐（`*-soft` 浅底、`*-line` 描边、`*-text` 文字色），另有圆角（6 / 8 / 12 / 16）、阴影（xs、card、md、lg、pop、press）、字号刻度 `text-11` … `text-24` 与 `bg-brand-gradient`。页面只用这些令牌类名，不写原型之外的数值。
- **字体**：Inter 与 Noto Sans SC 用 `@fontsource-variable/*` 随应用打包（内网浏览器不一定能访问 Google Fonts），字体栈与原型一致。
- **调接口**：前端用 `fetch` + `packages/contracts` 的 zod 模式解析响应（`src/lib/api.ts`），不用 `hono/client`：它要从前端引用后端的应用类型，与「前端不引用后端代码」的边界（ADR 0005 修订）冲突。ADR 0006 里「前端用 `hono/client` 获得端到端类型」以此为准。
- **路由与会话**：TanStack Router 用代码定义路由（`src/router.tsx`），登录后的页面挂在 `app` 布局下，`beforeLoad` 经 TanStack Query 取当前成员；未登录时若后端提供开发登录就去 `/dev-login`，钉钉扫码登录页（G11）随 05 号待办。路由加载出错时显示设计规范的「加载失败」空状态。ESLint 对 TanStack Router 的 `throw redirect()` 放行。
- **端到端**：Playwright 在 `apps/web/e2e`（`pnpm test:e2e`），视口 1440 × 900；本机运行时自己起 e2e api（4518，每次重建 `forcome_e2e` 库并灌示例数据）与前端预览（4519）。部署后对开发测试环境的冒烟由 03 号待办接上（设 `E2E_BASE_URL`）。
