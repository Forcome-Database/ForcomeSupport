# 前端用 Vite + React 单页应用，工厂工作台是同一项目里的独立构建入口

在已定的 shadcn/ui + Tailwind CSS v4（PRD D-10）之上，前端工程定为（2026-09-24 用户同意）：

- **框架**：Vite + React 19 单页应用，构建成静态文件，由 caddy 托管；不用 Next.js。
- **路由**：TanStack Router；查询参数经 zod 校验，筛选条件放在 URL 里，支撑 PRD 中「带筛选跳转到 P04 / P13」。
- **数据与组件**：TanStack Query（收到 SSE 的变化通知时让对应缓存失效）；TanStack Table + shadcn Data Table；react-hook-form + `packages/contracts` 的 zod 模式；shadcn Charts（Recharts）。客户端全局状态确有需要时用 Zustand。
- **设计令牌**：用一次性脚本把 `design/spec/ui.py` 的 `T` 转成 `globals.css`（shadcn 变量 + `@theme` 语义色），此后以 `globals.css` 为准；原型改令牌时同步修改两边。
- **密度**：`<html data-density>` 切换两套 CSS 变量；用户选择存在服务端的成员偏好里。
- **工厂工作台**：同一个 `apps/web` 项目、两个构建入口（`index.html`、`factory.html`），共享组件与令牌。公网入口只放行工厂入口的静态资源、`/api/factory/*` 和钉钉免登接口。主应用只支持桌面（≥ 1280px）；工厂工作台做响应式，以手机为主。
- **语言**：界面只做中文，文案直接写在组件里，不引入 i18n 框架。
- **测试**：Vitest + Testing Library；Playwright 端到端测试覆盖 PRD 第 13 节验收标准；视觉对照原型人工验收，不做像素级截图比对。

## Considered Options

- Next.js：多一个 Node 服务端进程；服务端渲染和 SEO 对内部系统没有价值。
- 工厂工作台与主应用打在同一个包里、只靠路由区分：外网虽然访问不了主应用的接口，但能下载到主应用的全部前端代码和接口路径。
- 单独建 `apps/factory`：组件和令牌要跨包共享，工程成本更高，却没有额外收益。
- 长期从 `ui.py` 生成令牌：会让生产代码依赖 Python 原型。

## Consequences

- 工厂接口必须集中在 `/api/factory/*` 前缀下，由后端再按「工厂人员 + 所属生产厂」鉴权；caddy 的路径白名单只是第一道防线。
- 原型与 `globals.css` 两份令牌并存，改令牌时需要人工同步。

## 修订（2026-10-04，待办 04 落地）

- **外壳**：顶栏分段导航取 `/api/me` 的 `nav`（后端按能力矩阵算好），当前项由 TanStack Router 的 `Link` 标 `data-status="active"`（地址以入口路径开头即算当前）。这是**有意偏离**设计规范板第 12 节组件对照的地方：对照表把「顶部导航」映射到 Tabs / ToggleGroup（胶囊样式），但顶栏入口是页面跳转、属于导航语义，Tabs / ToggleGroup 会给读屏器 tab / radio 的错误角色，所以用 `<nav>` + 链接实现；视觉与令牌仍与原型一致（浅灰轨道、选中白底描边与主色字）。页内的分段切换（不跳页面的）仍按对照表用 Tabs / ToggleGroup。右侧密度按钮（ghost 图标按钮）、站内通知铃铛的位置（31 号待办）、当前成员与头像菜单（shadcn DropdownMenu：审计日志 · 密度 · 退出登录）。第一阶段不显示店铺范围切换、全局搜索与导航角标。
- **路由与把关**：`/` 按 `home` 跳到默认首页；第一期页面路径 `/tickets`（P04）、`/aftersales/ledger`（P13，`/aftersales` 跳转到它）、`/reports`（P17）、`/settings/channels`（P18，`/settings` 跳转到它）、`/settings/team`（P20）、`/audit`（P27），登记在 `src/lib/pages.ts`（路径、G2 里的页面名、需要的能力）。没有能力时在原地址显示 G2（写明哪个角色能看、你当前的角色、找哪位管理员，按钮只有「返回首页」）；各页面的内容随各自的待办加进这些路由。
- **密度**：`globals.css` 定义舒适（默认）与紧凑两套 CSS 变量（设计规范第 12 节「密度」表：正文、次要、徽标字号，队列行内边距与行距，表格行高，面板内边距），`<html data-density>` 切换；页面用 `text-body`、`text-minor`、`text-badge`、`py-queue-row`、`gap-queue`、`h-table-row`、`px-panel-x`、`py-panel-y` 取值，顶栏、品牌标等固定尺寸不随密度变化。卡片内边距与正文、下拉菜单（含头像菜单的姓名）、空状态说明已用上这些工具类；顶栏本身固定。进入外壳前按 `/api/me` 的 `density` 先设好属性，切换时先改缓存里的当前成员（外壳据此改属性）再保存；保存失败退回原来的密度，并弹出 G5 失败浮层（带「立即重试」，重试成功后改为新的密度），会话已结束（401）时不弹。
- **浮层提示（G5）**：用 shadcn/ui 的 Sonner（`sonner`，不接 shadcn 默认带的 next-themes，只做浅色），容器 `src/components/ui/sonner.tsx` 挂在根路由：右上角堆叠、最多 3 条、间距 10、放在顶栏下方（上 68、右 16），默认 3 秒消失（成功与信息）；关掉 Sonner 自带的 Alt+T 快捷键（PRD D-20：快捷键只保留顶部搜索），读屏器播报区用中文名「浮层提示」。各页面不直接引用 sonner（lint 限定），统一经 `src/lib/notify.tsx`：`showError({ id, action, error, description, retry })` 弹失败浮层——卡片照原型 `toast('error', …)` 自绘（宽 360、12 圆角、md 阴影、红色叉号图标、13 / 600 标题、12 次要色说明、主色「立即重试」、右上角 ×），用 `toast.custom` 而不用 Sonner 自带的 action 按钮，因为原型把操作放在说明下方、关闭放在右上角，自带布局对不上；不自动消失。标题写「<动作>失败：原因」（原型例「保存失败：网络不可用」「发送失败：Gmail 接口超时」），原因用 `api.ts` 的 `failureReason`（接口错误取后端的中文说明，连不上服务器是 `NetworkError`，写「网络不可用」）。必须给重试或下一步：类型上 `retry` 与 `description` 至少给一个。「立即重试」用 Button 的处理中态防重复点击，成功后浮层消失，再失败标题换成「<动作>仍失败：原因」、浮层留着；同一件事用同一个 `id`，再失败替换旧浮层（重新挂载，不沿用上一次的重试状态）而不是再叠一条，之后成功就 `dismissToast(id)`；会话结束与退出登录时 `dismissAllToasts()`，不把提示留到登录页上。成功浮层、5 秒撤销浮层第一次用到的待办在 `notify` 里补上，同样照 G5；断网恢复后自动重试并再次提示结果（G4、G5）这次没做，由第一个实现断网整页提示（G4）的待办一并做。
- **会话结束**：`createQueryClient` 统一处理：任何接口返回 401（会话过期、被停用、在别处退出）都把缓存里的当前成员置空、撤掉全部浮层，外壳换成登录入口（开发登录；钉钉扫码登录页随 05）；不经查询缓存的请求（如失败浮层里的重试）出错时同样调 `endSessionIfUnauthenticated`；登录成功时清掉上一位成员留下的缓存。当前成员一分钟后过期，切回窗口时重新取，P20 改了角色不刷新页面也能跟上。站内通知轮询（31）与实时推送触发的重新拉取（18）发请求时带 `BACKGROUND_REQUEST_HEADER`，不算人的操作（ADR 0010 修订）。
- **类名合并**：`cn` 用 `extendTailwindMerge` 登记自定义的字号（`text-11` … `text-24`、`text-body` 等）、随密度的间距与自定义阴影（`card`、`pop`、`press`）；否则 tailwind-merge 把 `text-13` 当成文字颜色，会吃掉同一元素上的 `text-primary-foreground`（主按钮的白字变成继承的深色，待办 02 起就有、本待办做 G2 时发现）。

## 修订（2026-10-05，待办 07 落地）

- **表单**：react-hook-form 管表单状态与「有没有未保存的修改」（`formState` 是按读取订阅的代理，`isDirty` 要在渲染时读取才会更新）。点「保存」一律交给接口校验：接口一次返回全部字段错误（含查库才知道的重复，ADR 0006 修订），前端按 `fields` 用 `setError` 放到对应字段下方，并定位到最靠上的错误（顺序照表单自上而下）；改了哪个字段就先撤掉它的错误。不在前端另做阻断式的整体校验——要查库的错误只有接口知道，分两次报出会和原型 K8「三类错误同时报出」不一致；需要就地反馈的地方（如加入单个进线邮箱）用 `contracts` 里同一条规则。Radix Select 在选项还没渲染出来时会回调空串，`onValueChange` 里忽略空串。表单里的非提交按钮一律写 `type="button"`。
- **抽屉与确认（G7、G8）**：shadcn Sheet（右侧抽屉，宽度由使用处给，P18 为 440）与 AlertDialog（G6、G7、G8）按原型 `drawer()`、`dialog()` 改过样式。关闭抽屉（Esc、点遮罩、×、「取消」）都经 `onOpenChange(false)`，有未保存修改时先弹 G8「离开前保存修改？」（继续编辑 · 放弃修改 · 保存并离开，默认焦点在「继续编辑」）。带版本号的表单保存返回 409 时（G7）重新取最新数据，与打开时读到的那一版逐项比较写出「改了哪些项」，在表单顶部给警示横幅：「查看最新」换成最新数据重新编辑，「覆盖保存」二次确认（默认焦点在「取消」）后用最新版本号保存。后续表单直接用这几个共用件：`components/form-field.tsx`（`FormField`、`FieldError`）、`components/edit-conflict.tsx`（G7 的 `EditConflictAlert`、`OverwriteDialog`）、`components/unsaved-changes-dialog.tsx`（G8）。
- **组件**：按原型补上 Input（`controlClass` 是输入框、下拉触发器、多选触发器共用的外观）、Label（必填星号）、Select、RadioGroup、Tooltip（没有小箭头，Provider 挂在根路由）、Sheet、AlertDialog、Alert（`banner()`，先只有警示一种）、Skeleton、Badge（`chip()` / `state()` 带圆点 / `channel()` 渠道标识）、Table（列宽用 `<colgroup>` 照原型的 grid 模板；排序、筛选、分页的表格再接 TanStack Table）与 DropdownMenu 的勾选项；Button 补 `destructive`、`destructive-outline` 与文字链接（`variant="text-link" size="text"`，原型 `link()`）；`notify` 补 `showSuccess`（G5 成功浮层，3 秒消失）。原型里写死、令牌表里没有的几个颜色登记为令牌（`--input-hover`、`--destructive-active`、`--destructive-soft-active`、`--warning-banner`、`--warning-banner-icon`、`--success-card`、`--warning-card`、`--destructive-card`、`--scrim`），页面仍只用令牌类名。shadcn CLI 生成组件时会往 `package.json` 加一个名为 `cn` 的 npm 依赖并从它引用 `cn`，每次都要撤掉并改为 `@/lib/utils`。
