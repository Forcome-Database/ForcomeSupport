# 26: 历史邮件回放与 T0 切换

Status: ready-for-agent
Blocked by: 13, 16

规格：[第一期：报表与台账](../spec.md)

**What to build:** 上线第一天报表就有 90 天基线，且历史工单与实时工单口径一致。管理员命令：选定 T0 → T0 前启动 `watch` → 近 90 天邮件（收件与「已发送」）按 `internalDate` 升序单线程回放 → T0 后开启实时处理。回放复用实时流水线，只把「当前时间」注入为邮件时间：归并、关闭、重开按当时时间判断；工单编号日期取首封来信日期；回放模式下关闭一切提醒与通知。历史来信照常计算首次回复与 SLA；T0 时仍未回复的来信进入「待回复」并受 14 天规则约束。回放可断点续跑、重跑幂等。

- [ ] 集成测试：AC-P1-13（编号日期取首封来信日期；按邮件时间关闭与重开；无提醒、无通知）
- [ ] 集成测试：回放重跑不产生重复工单与消息
- [ ] 集成测试：T0 时未回复的历史来信所在工单，在最近一封来信 + 14 天后按规则关闭（PRD 6.1 起算口径）
- [ ] 集成测试：回放与 T0 后实时来信交界处不丢不重
- [ ] 操作手册写明切换步骤与回滚方式

## Comments
- 2026-10-05（待办 08）：实时收信走 `channel/gmail-sync.ts`（同步 → 入库 → 「来信已接收」→ `ticket/merge.ts` 归并），回放复用这条路即可：编号日期取来信的 `received_at`（internalDate），客户、店铺、渠道都在入库时定；入库的 `created_at` 与状态变更记录的时间取事务的「当前时间」（时钟），回放时注入为邮件时间。数据库约束按写入先后（UUIDv7）取最近一条状态变更，时钟拨回过去不受影响。邮箱的增量游标由 watch 建立（`channel.mailbox_sync`），T0 前先 watch、再回放 T0 之前的邮件，与规格的顺序一致。worker 的吞吐是每个队列空闲 2 秒轮询一次（ADR 0008 修订），回放大量邮件时要单线程直接驱动流水线或调 pg-boss 的批量与连续取。
- 2026-10-05（待办 10）：识别在入库时（`channel/recognition.ts`），回放走同一条路，平台通知与营销照常只入库归档。非生产环境的「重放来信」（`reset-inbound`，ADR 0013 修订）只是清空工具，不是本待办的 T0 回放。
