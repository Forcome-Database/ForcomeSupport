# 26: 历史邮件回放与 T0 切换

Status: resolved
Blocked by: 13, 16

规格：[第一期：报表与台账](../spec.md)

**What to build:** 上线第一天报表就有 90 天基线，且历史工单与实时工单口径一致。管理员命令：选定 T0 → T0 前启动 `watch` → 近 90 天邮件（收件与「已发送」）按 `internalDate` 升序单线程回放 → T0 后开启实时处理。回放复用实时流水线，只把「当前时间」注入为邮件时间：归并、关闭、重开按当时时间判断；工单编号日期取首封来信日期；回放模式下关闭一切提醒与通知。历史来信照常计算首次回复与 SLA；T0 时仍未回复的来信进入「待回复」并受 14 天规则约束。回放可断点续跑、重跑幂等。

- [x] 集成测试：AC-P1-13（编号日期取首封来信日期；按邮件时间关闭与重开；无提醒、无通知）
- [x] 集成测试：回放重跑不产生重复工单与消息
- [x] 集成测试：T0 时未回复的历史来信所在工单，在最近一封来信 + 14 天后按规则关闭（PRD 6.1 起算口径）
- [x] 集成测试：回放与 T0 后实时来信交界处不丢不重
- [x] 操作手册写明切换步骤与回滚方式

  **关键取舍**：
  ① 命令 `mail-replay`（`apps/server/src/mail-replay-command.ts`，入口 `src/mail-replay.ts`，部署子命令 `mail-replay`）：不加 `--confirm` 只看计划（T0、区间、各邮箱开始监听的时刻、worker 是否在运行），什么也不写——生产环境的「明确确认」就是这一步；加了才执行：各邮箱 watch（没有游标的建立、有的续订）→ 定 T0 → 列回放清单 → 逐封回放 → 补扫到 T0 → 完成切换。
  ② 复用实时流水线、只注入时钟与回放标记：`gmail-sync.ts` 拆出 `ingestById`，实时同步与回放共用同一段入库（去重、识别、未归属入队、发「来信已接收」「我方发信已同步」）；归并、回复识别、SLA、关闭都是原来的任务处理器（`createJobHandlers`，同 worker），回放的运行时 = 同一组库与队列 + 手动时钟（邮件时间）+ `replay: true`。回放只跑三个流水线队列（`mailReplayPipelineJobs`），其余（订单、钉钉、汇率）留给 worker。
  ③ 时限扫描不逐分钟扫 90 天：`ticket` 的 `nextTimeLimitAt` 给出下一个「扫描就会改东西」的时刻（SLA 截止 + 1 毫秒、最近来信 + 7 / 14 天、等来信的回复 + 24 小时），放在实时 worker 会扫的那一分钟（向上取整到整分；已过的放在这封邮件之后的下一个整分），时钟只往前走，结果与逐分钟扫描相同；最后补扫到 T0，T0 之后交给 worker 的每分钟扫描。
  ④ 切换状态 `channel.mail_cutover`（一行）与实时收信开关：只有「已切换」时 `channel.gmail_sync` 才入库，待切换、回放中什么也不做（不调 Gmail、不记成败）——从没同步过的邮箱是「未连接」，不会出同步延迟与连接异常（满足 Q2 的约束，不用改健康判断与 P18）。watch 照常由 worker 的拉取源做，所以生产环境的「T0 前启动 watch」不用另设步骤。完成切换在同一事务里给每个已 watch 的邮箱排一次同步。
  ⑤ 交界不丢不重：回放区间按 `internalDate` 截在 T0；增量从 watch 的游标开始（T0 不早于 watch 由 `mailbox_sync.watched_at` 保证，迁移 0032 新增），watch 之后、T0 之前到达的两边都看得到，按「邮箱 + Gmail 消息 ID」去重；回放清单之后才到、到达时间早于 T0 的由增量收下。
  ⑥ 断点续跑与幂等：回放清单 `channel.mail_replay_item` 记每封的到达时间与回放完的时刻（这封引起的任务都跑完才记）；中断后再执行同一命令接着做，时钟从上次回放到的那一封起走，中断时停在 active 的任务交回重试（没有 worker 时没人替它们过期）；已完成的再执行只报告。
  ⑦ 保护：worker 在连（`pg_stat_activity` 里 `forcome-worker*` 的连接）就拒绝，每回放一批（200 封）再查一次、途中连上就停下（退出码 1）；会话级咨询锁防两个回放同时跑；不删除任何数据。部署子命令 `--confirm` 时先停 worker、成功后再起，失败时 worker 保持停止并提示接着回放。
  ⑧ 回放里 `announceChange` 不发 NOTIFY（18 号衔接里的可选做法：几千封逐封回放时页面会一直刷新），完成切换时推一次「工单」「未归属店铺来信」。
  ⑨ 任务失败照实时 worker 处理：`drainJobs` 尊重重试间隔（真实时间等到点，时钟停在这封邮件），重试用完的记日志、计入完成输出、继续往下；按订单归并的最后一次尝试照常不关联订单建单（`lastAttempt` 经同一个 `runJob`）。
