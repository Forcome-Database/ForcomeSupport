**关键取舍**

- 部署脚本用 Node 写（只用 Node 自带模块），不用 bash：仓库的脚本都是 `.mjs`；Windows 上 `bash` 会解析到 WSL 而不是 Git Bash；纯逻辑能用 Vitest 测。服务器上只需 Node、git、Docker，不用 `pnpm install`。
- 冒烟放在一次性容器里，只把本环境 caddy 的根证书加进容器内 Chromium 的证书库（NSS），经 Compose 网络按内网域名访问 caddy（网络别名模拟内网 DNS）；没有用宿主机 Playwright + `ignoreHTTPSErrors`：那样浏览器不校验证书，「受信」只能另证；本机 Windows 的 Chromium 只读系统证书库，不能改。容器因此与 Linux 服务器上完全一样，服务器也不用装浏览器。caddy 写的证书文件只有 root 可读，冒烟容器以 root 运行（Playwright 默认关 Chromium 沙箱）；报告用 `docker cp` 取出，不挂宿主机目录，免得文件属主变 root。
- 宿主机侧的核对用 Node `tls`/`https` 连 127.0.0.1 并以内网域名做 SNI 与证书域名核对，不改 hosts 文件、不依赖本机 curl（Windows 自带 curl 走 schannel，对内部 CA 报「吊销状态未知」，手册写了 `--ssl-no-revoke`）。
- 环境文件是变量的唯一来源：脚本调 Compose 时把环境文件里有的变量从子进程环境去掉（Compose 让 shell 变量优先于 `--env-file`）；代理变量在 Compose 里大小写都显式给出（undici 优先小写，Docker 客户端配置代理时会注入小写）；`NO_PROXY` 写成 `.dingtalk.com`（各实现都按子域名匹配）。本机第一次部署时脚本生成 `deploy/.env.staging`（随机十六进制口令，不进 git）；口令限 URL 安全字符，因为直接拼进连接串。
- 端口：开发测试 4510（HTTPS，本机只开在 127.0.0.1）、4511（PostgreSQL，只开在 127.0.0.1）；4512–4513 留给生产。
- 部署失败不回滚：开发测试环境停在失败处便于排查；migrate 在启动服务之前，迁移失败时 api、worker 仍是上一版本。每次部署都跑 seed（加载步骤要求幂等）。启动服务后核对 api、worker、caddy 运行的都是本次构建的镜像标签。
- postgres 镜像用固定标签 `forcome-postgres:18`，镜像不变时数据库容器不重建；自建镜像一律 `pull_policy: never`，不会去镜像仓库拉同名镜像。
- 发信白名单放在真实现这一层（离网络最近，业务代码怎么调用都绕不过去），Fake 不检查；白名单条目（可写 `@域名`）与收件地址（必须是单个完整地址，带显示名或多个地址一律不放行）用两套正则，因为校验的对象不同。模板里 `MAIL_SEND_ALLOWLIST_ONLY` 留空走默认，免得照抄到生产后一封信也发不出。
- Fake 回放放在 `createIntegrationClients`（api、worker、e2e api 共用的进程入口），测试工具不自动回放；目前没有登记任何客户端，回放是各集成待办实现 `replay` 后才生效的扩展点。
- 冒烟跑 `apps/web/e2e` 全部用例（规格：端到端在开发测试环境上合并后运行）；以后的用例要能在长期运行、已灌示例数据的环境上重复执行（已写进规格）。
- caddy 加了 `nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`，去掉 `Server` 头；没有加 HSTS：内部 CA 推广期间，没装根证书的浏览器有 HSTS 就不能临时放行，切 DNS-01 后再考虑。
- Node 24：照 README 与待办 01、02，用会话临时目录里的便携 Node 24.21.0（`corepack enable` 只写进该目录）与 corepack 的 pnpm 10.34.6，没有改系统配置；部署脚本本身 Node 22 也能跑。

**自己写而没用现成库的部分**

- 部署脚本（`deploy.mjs` 与 `deploy/lib/`，约 450 行含测试）：容器编排交给 Docker Compose，脚本只把「构建 → migrate → seed → 起服务 → 核对 → 冒烟 → 报告」串起来并做本项目的核对（APP_ENV 与环境相符、镜像版本、根证书）。Ansible、Kamal 面向远程多机部署，要在 Windows 本机另装 Python 或 Ruby 工具链，Kamal 还依赖镜像仓库与 SSH，不合「先在本机 Docker」；Make 在 Windows 上没有。环境文件解析用 Node 内置的 `util.parseEnv`，Playwright 结果取它自带 JSON 报告的统计，证书指纹用 `crypto.X509Certificate`。
