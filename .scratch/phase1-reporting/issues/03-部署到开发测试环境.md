# 03: 部署到开发测试环境

Status: claimed
Blocked by: 02

规格：[第一期：报表与台账](../spec.md)

**What to build:** 合并到 main 后系统自动出现在内网的开发测试环境里，团队可以用浏览器访问。完整 Compose（`caddy`、`api`、`worker`、`migrate`、自建 `postgres` 镜像），caddy 托管前端静态文件并以内网子域名 + DNS-01 证书提供 HTTPS（会话 Cookie 为 `Secure`）。出站设 `HTTPS_PROXY` 与 `NO_PROXY`（ADR 0003）。内网自托管运行器以独立系统用户、只能操作开发测试 Compose 项目的标签领取部署任务；部署前先跑 `migrate`；部署完成后对该版本跑 Playwright 冒烟。开发测试环境默认全部用 Fake，并按已建模块加载示例数据夹具（随各模块的待办逐步补齐）。

**按用户 2026-10-04 口径调整**（经协调者转达）：服务器与 GitHub 暂未就绪，先在本机用 Docker 部署与测试，部署脚本与 Compose 原样搬到 Linux 服务器；暂不上 GitHub，「合并到 main 触发部署」「Actions 上报告结果」「内网自托管运行器」本期改为本机部署脚本，自托管运行器写成上 GitHub 后的启用说明；内网 HTTPS 先用 caddy 内部 CA（`tls internal`），公司域名与 DNS-01 到位后切换，会话 Cookie 仍为 `Secure`；外部资质只有钉钉企业内部应用，开发测试环境默认全部 Fake；暂无出站代理。下列验收项按此改写，保留每一项的验证意图，原措辞与对应关系见 Comments。

- [ ] 一条命令 `pnpm deploy:staging` 部署到开发测试环境：构建镜像 → 先跑 `migrate` → 灌示例数据 → 起 `forcome-staging` Compose 项目；上 GitHub 后由 main 上 CI 通过触发的部署工作流，在开发测试运行器（独立系统用户、只能操作开发测试 Compose 项目的标签）上调用同一脚本，PR 与 main 的构建测试仍在云端运行器（工作流已写好并通过 actionlint，启用步骤写进部署说明）
- [ ] 内网域名 HTTPS 可访问（caddy 内部 CA）：用导出的根证书验证证书链与域名有效，冒烟的浏览器只信任这张根证书且没有证书错误；会话 Cookie 为 `Secure`；部署说明写明员工浏览器安装根证书、以后切到 DNS-01 的步骤
- [ ] 部署后 Playwright 冒烟（开发登录 → 看到顶栏）自动运行，部署脚本输出结果并留存报告（上 GitHub 后同一份报告写入 Actions 的作业摘要，冒烟报告作为产物上传）
- [ ] 开发测试环境的外部客户端默认为 Fake；默认禁止向白名单外地址发信的开关已就位
- [ ] 运维所需清单（放行域名、`NO_PROXY`、内网 DNS）写进部署说明；`HTTPS_PROXY`、`NO_PROXY` 可配置（暂无代理，不实测经代理出站）；部署说明含迁移到 Linux 服务器的步骤
