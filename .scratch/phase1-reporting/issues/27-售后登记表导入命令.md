# 27: 售后登记表导入命令

Status: ready-for-agent
Blocked by: 20, 21

规格：[第一期：报表与台账](../spec.md)

**What to build:** 客户现有的售后登记表一次性进入台账。命令行导入（不用模型）：读取表格，按映射表转为售后单（照 R-AS-08；原表的退款或补偿金额映射到额外赔偿），创建路径「历史导入」；映射表以配置形式存在，拿到真实表格后再定内容；缺失字段标「历史导入」；原表无原币时直接按美元导入并标注；按原表的费用发生日取汇率，原表没有费用发生日时取原登记日期（PRD 第 14 节）；编号日期取原登记日期、序号全局递增。历史导入的单不计入完整率。提供试运行模式（只报告将导入的行与错误，不写库），导入结果输出行级错误报告；重跑幂等。

- [ ] 集成测试：用样例表格导入后台账列表可见，标注「历史导入」
- [ ] 集成测试：导入的已完成单不影响当月完整率
- [ ] 集成测试：无原币的行按美元导入并标注；有原币的按原表费用发生日取汇率，没有费用发生日时取原登记日期
- [ ] 集成测试：试运行不写库；重跑不产生重复售后单
- [ ] 映射表字段待客户样本到位后在本待办 Comments 中补充

## Comments

- 2026-10-05（待办 19 留下的衔接）：创建路径已有「历史导入」（`aftersalesOrigins` 的 `history_import`）；售后单表除单号、状态、创建路径、店铺外都可空，正适合缺字段的导入行。编号用 `core` 的 `nextBusinessNumber(tx, 'aftersales', 原登记日期)`；若要沿用原表的单号，写入后用 `reserveBusinessNumbers` 把全局序号推到最大值之后（示例台账的加载步骤就是这样做的）。
- 2026-10-05（待办 20 留下的衔接）：导入时按原表的费用发生日（没有时取原登记日期）取汇率，直接用 `aftersales/fees.ts` 的 `convertFees(db, 费用, 日期)`——当天没有取此前最近一个有汇率的日期；汇率表在第一次同步时已装入欧洲央行 1999 年起的全量历史（`core` 的 `syncExchangeRates`），早年的登记也能折算。原表没有原币、直接按美元导入的行，币种记 USD（美元值等于原值、没有汇率），「按美元导入」的标注要另加一列或复用「历史导入」的缺失标记，由本待办定。
- 2026-10-05（待办 21 留下的衔接）：
  - 历史导入的单不计当月登记完整率、不在「筛出缺字段的 N 单」里（`aftersales/ledger.ts` 的 `completedIn`：`origin <> 'history_import'`），但在台账照常标「待回填」与「缺 N 项」（`missing` 只看状态，不看来源），售后负责人可补登（AC-P1-07、PRD v2.18）。导入的已完成单写 `completed_at`（原表没有完成时间时可空，表上的 CHECK 只要求有完成时间的单必须是已完成）；已取消的单写 `cancel_reason` / `cancelled_at`，保留项列按原表（没有时按全部保留）。
  - 测试工具 `t.addHistoryImport(…)`（`apps/server/test/harness.ts`）现在直接写售后单表造历史导入的单，是 ADR 0005「待办 21 落地」修订登记的例外；导入命令落地后改调导入命令，并删掉这条例外。
- 2026-10-05（待办 22 留下的衔接）：台账按费用发生日筛选（默认本月），售后成本视图也按它归期；费用发生日为空的单在任何日期区间都不会列出、也不计入按月的售后成本。导入时一定写费用发生日（规格：原表没有费用发生日时取原登记日期）。导入的单在台账照常算承担金额（`contracts` 的 `costShares`）；缺比例的历史单承担两列写「—」或「待回填」，合计行只加有比例的行。
