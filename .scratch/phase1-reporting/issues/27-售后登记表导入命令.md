# 27: 售后登记表导入命令

Status: resolved
Blocked by: 20, 21

规格：[第一期：报表与台账](../spec.md)

**What to build:** 客户现有的售后登记表一次性进入台账。命令行导入（不用模型）：读取表格，按映射表转为售后单（照 R-AS-08；原表的退款或补偿金额映射到额外赔偿），创建路径「历史导入」；映射表以配置形式存在，拿到真实表格后再定内容；缺失字段标「历史导入」；原表无原币时直接按美元导入并标注；按原表的费用发生日取汇率，原表没有费用发生日时取原登记日期（PRD 第 14 节）；编号日期取原登记日期、序号全局递增。历史导入的单不计入完整率。提供试运行模式（只报告将导入的行与错误，不写库），导入结果输出行级错误报告；重跑幂等。

- [x] 集成测试：用样例表格导入后台账列表可见，标注「历史导入」
- [x] 集成测试：导入的已完成单不影响当月完整率
- [x] 集成测试：无原币的行按美元导入并标注；有原币的按原表费用发生日取汇率，没有费用发生日时取原登记日期

**关键取舍**

- **整体一个事务、一行一个保存点、试运行最后回滚**：
  - 试运行与正式导入走同一条路径，报告的单号、错误与正式导入一致（集成测试核对两者单号相同）；
  - 坏行只回滚自己，编号也不占用；
  - 咨询锁保证同一时间只跑一次导入，行标识的唯一约束是第二道保险；
  - 代价：导入期间编号计数行一直被占用，新建登记要等导入结束。导入是上线前的一次性操作、几千行几秒，所以接受，写进 ADR 0006 与部署说明（以后要在业务时段导入大表时改分批）。
- **导入记录单独成表，不在售后单表上加列**：售后单表与第二期共用，导入特有的行标识、来源行、标注与原值放在 `aftersales.history_import`（只增不改）；重跑跳过的行在报告里带出当时存的标注，测试借此核对标注已经落库。缺的字段不另存，按 R-AS-08 随时算。
- **状态按原表建档，不经迁移表**（ADR 0008 修订）：这是系统外已经走到的状态，不是已有单的状态变化，与示例数据的加载步骤同理。
- **编号按原登记日期先后发号**（同一天按原表行序），序号接在已有的单之后；`startOfBusinessDate(原登记日期)` 给编号日期。
- **不推断缺的字段**：站点、比例、负责人、生产厂都按原表，缺的算缺、可补登。
- **读表时单元格只留四种值**：公式取结果，百分比格式写成「50%」，Excel 日期单元格按 exceljs 给出的 UTC 年月日时分就是原表看到的值，按北京时间理解；CSV 一律按文字，交给逐行转换按字段解析。
- **CSV 只收 UTF-8**：Excel 默认另存的 GBK 会乱码，直接报错让人另存，不猜编码。
- **命令拆成入口与组合函数**（评审意见）：命令本身在 `import-aftersales-command.ts`，入口只组装运行时，测试用测试库执行同一个函数（同 `reset-inbound.ts` / `reset-inbound-data.ts` 的分法）。
- **导入的插入列没有并入 `registrationColumns`**：后者吃规范化的 `RegistrationInput`（空串、比例两侧输入），导入是 `HistoryRecord`（null、工厂比例），硬合并反而更绕（评审认可）。
- **Node 24**：照 README「开发」，便携 Node 24.21.0 复制到本会话临时目录，只在会话命令里前置 PATH，pnpm 10.34.6 经 corepack 取用；没有改系统配置。

自己写的只有两处：
- **日期解析**（约 20 行）：原表的写法只有「2026-03-02 / 2026/3/2 / 2026.3.2 / 2026年3月2日」加可选时刻与 Excel 日期单元格几种。仓库没装 dayjs、date-fns；装上后严格解析也要逐个列格式。一条正则加 UTC 往返校验更直接，单元测试覆盖。
- **金额解析**（约 15 行）：只认数值与带千分位的数字文字，带币种符号的不认（墨西哥比索也写 $，猜不准）。numeral 之类的库会宽松接受各地写法与符号，反而要关掉。
