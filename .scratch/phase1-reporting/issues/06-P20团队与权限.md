# 06: P20 团队与权限

Status: claimed
Blocked by: 05

规格：[第一期：报表与台账](../spec.md)

**What to build:** 管理员在 P20 管理谁能做什么，按 PRD P20 与其「第一阶段」小节。页签「成员」：全宽表（成员、钉钉部门、角色（可多个）、数据范围、状态、最近登录；第一期不显示「语言」列，页头不显示备用审批人）；「从钉钉添加」右侧抽屉，从钉钉通讯录选人并必填角色（可多选，第一期不能选生产厂对接人）与店铺范围；修改角色与数据范围后在吸底保存栏统一保存（K6），未保存离开提示 G8。页签「角色权限」：只读权限矩阵（K17），直接由 `contracts` 的能力矩阵渲染，只显示第一期已上线的能力行。所有修改写审计。停用成员的改派流程见待办 23。

- [ ] 管理员从钉钉添加成员，不填角色或店铺范围时无法保存；角色选项里没有生产厂对接人
- [ ] 修改角色与店铺范围后，该成员下一次请求即按新权限生效
- [ ] 角色权限页签与能力矩阵常量一致（同一数据源渲染），只列第一期已上线的能力
- [ ] 非管理员访问 P20 显示无权限
- [ ] Playwright：添加成员 → 分配角色 → 以该成员开发登录进入默认首页

## Comments

- 2026-10-05（待办 07）：设置页外壳已就位——`apps/web/src/pages/settings/settings-layout.tsx`（左侧设置菜单「渠道与店铺 · 团队与权限」+ 页头 `SettingsHeader`），P20 先挂了空的 `team-page.tsx`，内容加在里面即可。成员「数据范围」的可选店铺：`GET /api/channel/store-options` 按当前成员的店铺范围过滤，管理员被授权为部分店铺时只会列出那几个——授权选择要列出全部店铺，本待办需另定（例如 `channel` 再导出一个只给管理员能力用的全部店铺选项，或管理员一律为全部店铺），并写回 ADR 0010。抽屉、确认弹窗、Select、RadioGroup、Badge、Table 等组件已按原型改好；表单写法（保存交给接口一次报全字段错误、G7 冲突横幅、G8 未保存离开）见 ADR 0007「待办 07 落地」修订，直接用 `apps/web/src/components/` 下的 `form-field`、`edit-conflict`、`unsaved-changes-dialog`（用法参照 `store-drawer.tsx`）；P20 的吸底保存栏另做。

- 2026-10-06（待办 31）：站内通知按接收人当前的店铺范围过滤（ADR 0010「待办 31 落地」修订）：范围收窄后范围外店铺的通知不显示、不计未读，「全部已读」也只标看得到的。P20 能改成员的店铺范围后，补一条经主接缝的集成测试：范围收窄期间「全部已读」，再放宽，范围外的那条照常是未读（`apps/server/test/notifications.int.test.ts` 现在只能用一开始就受限的成员测「看不到」）。接收人按 11.4 的角色在发送时取在职成员，改角色、停用后只影响以后的通知。

- 2026-10-06（待办 05）：成员表现在是钉钉通讯录的镜像——通讯录里的人都同步成成员，新人没有角色、店铺范围为空（`all_stores` 假、`store_ids` 空），钉钉离职的停用（原因 `dingtalk_left`）。P20「成员」表列有角色的成员；「从钉钉添加」就是从在职、没有角色的成员里选人再分配角色与店铺范围（必填），不用另外调钉钉。可用的字段：`member.email`（姓名 + 邮箱列）、`member.dept`（钉钉部门，已算好路径）、状态的叫法 `contracts` 的 `memberStatusLabels`（已启用 / 已停用，照原型 P20）；「最近登录」可取审计 `auth.login` 或另加列。通讯录同步只改资料时不动版本号，停用与恢复在职时动（P20 保存带版本号，碰上会 409，按 G7 处理）。成员的审计快照已有 `member`（姓名、钉钉部门、状态、角色，`contracts/audit.ts`），P20 的修改可在它上面加店铺范围等字段并登记新动作。测试：`t.addMember({ dingtalkUserId, … })` 后在 Fake 钉钉放同 ID 的人（`t.clients.fake(dingtalkClient).addUser(…)`，否则对账会当他离职），扫码登录 `t.scanLogin(钉钉用户 ID)`；Playwright 可用开发登录，或登录页 + 模拟扫码（`apps/web/e2e/dingtalk-login.spec.ts`）。范围收窄后「全部已读」的那条集成测试（待办 31 的留言）同样在这里补。
