**关键取舍**

- 成员表只是「有客服系统角色的成员」的视图，没有另建表：成员都来自钉钉通讯录（待办 05），没角色的就是候选，「添加」就是给候选分配角色与范围。
- 吸底栏整批保存而不是逐行：K6 是页面级「统一保存」，一次请求、一个事务，「至少一位在职管理员」要看整批改完的结果才能判断。
- 改角色与范围不删会话、不要求重新登录：每次请求从成员表读（ADR 0010），下一次请求即生效；被改的人前端缓存的 `/api/me` 一分钟内过期（ADR 0007 待办 04）。
- 冲突（G7）以「开始改时依据的那一版」为准，而不是页面最新取到的数据：页面刷新数据不会让未保存的修改悄悄覆盖别人的修改。
- 「查看最新」只放弃冲突那几个人的修改，其他人的修改留着；「覆盖保存」只对冲突的人换最新版本号。

**自己写而没用现成库的部分**

- 页面级的待保存修改（`team-edits.ts`，约 200 行含冲突与保存后的处理）：react-hook-form 管的是一张表单的字段；这里是表格里多行多格、每行各带依据的版本号，`useFieldArray` 装得下值，但依据版本、冲突比较、保存期间又改的处理都要另写，引进来反而多一层映射。
- 吸底保存栏（`save-bar.tsx`）：shadcn/ui 没有对应组件，照原型 `save_bar()` 写约 70 行。
- 断网后自动重试：TanStack Query 的 `onlineManager` 只会暂停写操作、恢复后静默补发，K6 要求当场告诉用户、恢复后自动重试并给不同的浮层，所以 `networkMode: 'always'` 加 `online` 事件，约 20 行。
- 角色权限矩阵用 CSS grid 的 div（`role="table"`）而不是 `Table`：原型就是 grid（72 / 1fr / 6×120 列、组名只写在组的第一行）。其逐格对照的单元测试用字符串解析静态渲染结果，没有为它引入 jsdom。
- 选人下拉用已装的 cmdk（shadcn Command）、角色勾选用已装的 DropdownMenu 勾选项、数据范围用 Popover + RadioGroup + Checkbox，没有引入多选库。
