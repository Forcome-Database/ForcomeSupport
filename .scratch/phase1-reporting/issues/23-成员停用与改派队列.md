# 23: 成员停用与改派

Status: ready-for-agent
Blocked by: 06, 19, 31

规格：[第一期：报表与台账](../spec.md)

**What to build:** 成员离开时，他负责的售后单有人接手。P20 手工停用（K10）：二次确认弹窗列出该成员负责的进行中售后单，要求为每张选接手人（只列有该店铺数据范围的售后负责人），选齐后「改派并停用」，改派与停用在同一事务内完成并记审计；没有可接手的售后负责人时「改派并停用」不可用并写明原因（AC-ST-02）。钉钉离职自动停用时，`org` 发「成员已停用」事件，`aftersales` 把其负责的进行中售后单标记为「待分配」进入客服主管的改派队列（归属标记，不改业务状态），客服主管收到站内通知（AC-ST-05）。客服主管或售后负责人可在 P13 用「负责人：待分配」筛出这些单并改派负责人（只能改给有该店铺范围的售后负责人）。

- [ ] 集成测试：AC-ST-02（负责 2 张进行中售后单 → 弹窗要求选接手人；选好后停用、负责人变更记审计）
- [ ] 集成测试：没有其他售后负责人可接手时停用被拒绝并返回原因
- [ ] 集成测试：AC-ST-05（离职 → 自动停用、会话失效、售后单进入改派队列、客服主管收到站内通知）
- [ ] 集成测试：改派后售后单状态不变，负责人变更记审计；改派给非售后负责人被拒绝
- [ ] 集成测试：跨模块只经事件联动，`org` 不直接读写售后单表
