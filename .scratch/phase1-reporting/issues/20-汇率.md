# 20: 汇率

Status: resolved
Blocked by: 19

规格：[第一期：报表与台账](../spec.md)

**What to build:** 台账里的比索、加元金额都有可追溯的美元折算。`core` 每日任务经代理读取欧洲央行 `eurofxref-daily.xml`（补数用 90 天或全量历史文件），以 EUR 交叉计算 USD/MXN、USD/CAD 入库；主源失败用 Frankfurter 备用；「按日期取汇率」缺失时返回此前最近一个有汇率的日期，并带实际日期与来源（E-20）。台账保存与修改时，按费用发生日取汇率，每个金额保存原币、汇率、汇率日期与来源、冻结美元值（四舍五入到分）。售后负责人可修改某条记录的汇率，记审计。P13 金额旁显示美元折算，非美元金额一律显示原币与汇率日期（例「MX$889.00 · 汇率 09-10」）。

**关键取舍**

- **冻结，只增不改**
  - 每个费用项在保存时冻结自己的汇率与美元值；台账、合计与报表只读冻结值，不按汇率表重算。
  - 汇率表只增不改，同步时已有的日期跳过。
  - 因此之后的每日更新、主源恢复、备用源补数都不会改已保存的金额（E-20「恢复后不回改」，对应验收第 4 条）。
- **美元金额与数据约束**
  - 美元金额不折算：汇率、汇率日期、来源三列为空，美元值等于原值；这些组合由数据库约束 `*_conversion_check` 把关。
  - 「有金额就有美元值」由应用把关（`feesOf`），没写进数据库约束。原因是加列时，开发库与开发测试库里已有一张非美元的示例单 S-20260911-0020，迁移取不到它当时的汇率，只能由加载步骤按夹具补齐；生产库此时还没有台账数据。
  - 本机开发库实测：迁移 0013、0014 之后，0020 还缺美元值；`pnpm db:seed` 之后补成 $49.39、汇率 09-10、来源欧洲央行。
- **同步区间与挑文件**
  - 从库里最近一个有汇率的日期的次日，取到今天（北京时间）。
  - 库里一条都没有时，从欧洲央行最早的 1999-01-04 取全量（约 6,900 天、1.4 万行，分批写入），这样历史导入（27）也能按原日期折算。
  - 真实现按区间挑最小的文件：区间起点在 85 天以内时先取 daily，中间没缺工作日就用它；否则取 hist-90d；还不够才取全量。
  - 中间缺工作日，只会发生在之前的同步失败过：欧洲央行按工作日连续公布，假日本来就没有数据。
- **备用源**
  - 只在主源抛错时才用 Frankfurter，并加 `providers=ECB`：它的数据同样来自欧洲央行，两个来源口径一致。
  - 两个来源都失败时任务失败，30 分钟后重试，最多 3 次，不写任何数据；之后按日期取汇率会自然回退到此前的日期。
- **接口定义在使用方**：同步写在 `core`，而 `core` 不能依赖 `integration`，所以两个来源的接口 `ExchangeRateSource` 定义在 `core`，由入口把客户端交给任务处理器（见 ADR 0009 修订）。
- **前后端口径一致**：抽屉里的即时折算与后端冻结用同一套函数（`contracts` 的 `usdOf`），显示的就是保存后的值。填了金额的非美元项（0 也算）与保存时一样需要汇率。
- **改汇率**：先比版本号（不一致返回 409，G7），再把错误一次列全。审计 `aftersales.change_rate` 记完整的前后值，与新建时用同一个快照函数。
- **表下说明**：原型里是一段话，同时写汇率折算、承担计算、「待回填」与行尾「更多」，后面几样本期还没有，所以随 22 一起加（已写进 22 的 Comments）。
- **Node 24**：照 README「开发」与待办 01 的做法，把便携版 Node 24.21.0 复制到本会话的临时目录，只在会话命令里把它放到 PATH 前面；pnpm 10.34.6 经 corepack 运行。没有改系统配置。

**自己写而没用现成库的部分**

- `calendar-date.ts` 的 `addDays`、`isWeekday`：两个十来行的函数，用 `Date` 的 UTC 零点换算就够。仓库里没有日期库，为两次调用引入 date-fns 不划算。
- `integration/http.ts`：HTTP 本身用的是 undici（`fetch` + `EnvHttpProxyAgent`）。自己只写了一层包装，把超时、非 2xx 和网络错误翻译成 `faults.ts` 那一套错误。这一层就是 ADR 0009 约定的「同一个 HTTP 客户端工厂」，没有对应的库可用。
- 欧洲央行按区间挑文件、Frankfurter 的返回按日期合并：这是两个接口本身的用法。社区包要么只取最新一天，要么依赖别的接口，都不支持「读欧洲央行原始文件，Frankfurter 作备用」。
- 十进制运算用 big.js，XML 解析用 fast-xml-parser，都没有自己写。
