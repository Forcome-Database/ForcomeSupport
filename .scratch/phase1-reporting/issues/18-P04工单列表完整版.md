Status: claimed
Blocked by: 16

规格：[第一期：报表与台账](../spec.md)

**What to build:** P04 成为可用的工单工作台（只读），按 PRD P04「第一阶段」小节与状态 I16。筛选：状态（待回复 / 等客户 / 已解决 / 已关闭）· 渠道（亚马逊 / Shopify / 邮件）· 店铺 · 站点 · 来源（客户 / 生产厂 / 其他供应商）· 最近来信（默认近 30 天），条件经 zod 校验写入 URL，可分享与回退；另支持只走 URL 的下钻参数（客户来信触发的新建或重开日期、来信到达日期、来信 SLA 结果、渠道），以可移除的「来自报表」芯片显示；按来信下钻时列出含这些来信的工单，芯片写「N 封来信 · M 张工单」（PRD P17）。列：工单号 · 主题 · 来源（非客户时显示徽标）· 渠道与店铺（含站点）· 客户 · 订单号 · 状态 · SLA 剩余 · 最近来信（当天只写时分）。SLA 列：待回复显示最早一封未回复应回复来信的剩余或「已超时」（R-SL-03 格式与颜色，内部目标加「· 内部」），没有应回复来信写「—」；等客户写「已回复」；已解决、已关闭写「—」。默认排序：已超时在前，其后按剩余升序，再按 待回复 → 等客户 → 已解决 → 已关闭，组内最近来信倒序；表头可排序；分页；筛选无结果 I10；加载骨架。数据变化经 SSE 推送后自动刷新（`NOTIFY` → api → 浏览器缓存失效）。点击行进入 P05。没有指标行、快捷视图、批量条、选择框、优先级、意图、情绪、标签、负责人、导出、新建工单。店铺范围强制过滤。
