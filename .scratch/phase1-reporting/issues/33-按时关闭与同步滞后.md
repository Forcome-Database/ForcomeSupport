# 33: 按时关闭与同步滞后

Status: claimed
Blocked by: 16, 17

规格：[第一期：报表与台账](../spec.md)

**What to build:** 时限扫描的「按时关闭」（等客户、已解决 7 天，待回复 14 天，PRD 6.1 第一阶段迁移表）只看库里的 `ticket.last_inbound_at`，不管来信有没有同步进来。Gmail 同步滞后（断线、补拉）时，客户其实在到期前已来信、只是还没入库，扫描照样关闭；随后来信入库，按 30 天内重开（R-TK-01），多出一对关闭 / 重开（影响 P17 工单量里的重开计数与 P05 状态流转）。另外 P05 状态流转里「按时关闭」一步的业务时刻是读取时重算的（「关闭时刻之前已到达的最近来信 + 期限」），补拉进来的信日期早于关闭时刻，就会显示成晚于关闭时刻的时间。这是 16、17 号功能的技术缺陷（协调者 2026-10-14 决定在第一期修，不留到 29）。开发测试环境的示例回放也因此偶发：worker 逐封回放示例来信时，每分钟的扫描落在两封之间就会关了再重开。

协调者给的方向（实现时可按技术判断调整，写回 ADR 0008）：

- 扫描按时关闭前，确认该工单所属店铺的进线邮箱已经同步到到期时刻之后（例如邮箱的最近同步成功时间 ≥ 到期时刻；回放模式按回放时钟）；没同步到就本轮不关，等下一轮。切换前（`channel.mail_cutover`）照 26 号的口径。
- 关闭时把所用的到期时刻存进状态变更记录，P05 状态流转直接用它，不再读取时重算。
- 非生产的示例回放：让示例来信在开始跑时限扫描之前全部入库并归并完（或示例回放走回放模式），消除开发测试环境冒烟的偶发失败。

- [ ] 集成测试：邮箱同步滞后（最近同步成功早于到期时刻）时不关闭；同步追上后下一轮照常关闭，原因与时刻不变
- [ ] 集成测试：滞后期间到期前到达的来信补拉进来后，工单照常回到待回复，没有多出的关闭 / 重开（工单量的重开计数不变）
- [ ] 集成测试：P05 状态流转里按时关闭的业务时刻 = 关闭时存下的到期时刻，不晚于关闭时刻；历史回放（mail-replay）的关闭时刻照旧按邮件时间
- [ ] 非生产的示例回放不再与时限扫描交错（集成测试或 worker 启动顺序的测试）
- [ ] `ticket-detail.spec.ts`「坐席打开 Oliver Grant 的工单…状态流转（I18 ①）」在连续两次 `pnpm deploy:staging --reset-inbound` 的冒烟里都通过
- [ ] ADR 0008 修订（按时关闭的前提与业务时刻的存法）
