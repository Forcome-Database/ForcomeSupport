# 15: 未归属店铺队列与指定店铺

Status: ready-for-agent
Blocked by: 05, 10, 14, 16, 31

规格：[第一期：报表与台账](../spec.md)

**What to build:** 识别不出店铺的来信不丢，客服主管一步把它归位，管理员登记新店铺后自动归位。收件邮箱未登记的来信进入「未归属店铺」来信队列（尚未归并成工单），SLA 按原到达时间计，平台按发件域判断（亚马逊域按亚马逊 24 小时，其余按内部目标）；客服主管收到站内通知（待办 31）与钉钉工作通知（E-13）。P04 上只对客服主管显示「未归属店铺 N」入口与队列（I17）：列为来信（客户 + 主题）· 识别依据（收件地址与头字段名 + 「未登记」）· 到达 · SLA · 指定店铺；队列对客服主管不受店铺数据范围限制（来信尚无店铺），指定时下拉只列其授权店铺；没有 ✦ AI 推荐。主管点「指定」后前端先移出该行并显示 5 秒撤销浮层，窗口结束后才提交；提交后按 R-ST-02 重新识别站点、关联订单并归并成工单，SLA 保留原到达时间；操作记审计。待办 07 新增店铺或为现有店铺增加进线邮箱（含别名）后，队列中收件地址匹配的来信自动按同一流程归位，客服主管收到站内通知。

- [ ] 集成测试：AC-TK-09（未登记邮箱来信 → 进入队列，不建工单，SLA 照常计时）
- [ ] 集成测试：AC-TK-11（指定店铺 → 关联订单并归并成工单，SLA 仍按原到达时间，不生成草稿）
- [ ] 集成测试：AC-P1-15（撤销窗口内撤销 → 来信回到队列、不产生工单；不撤销 → 窗口后归并）
- [ ] 集成测试：AC-P1-16（新增匹配的店铺后来信自动归位，客服主管收到站内通知）
- [ ] 集成测试：店铺范围受限的客服主管能看到队列，但指定为未授权店铺被拒绝；坐席请求队列接口被拒绝
- [ ] Playwright：客服主管在 P04 打开队列、指定店铺、撤销

## Comments

- 2026-10-02：按 PRD v2.11（D-24）改为撤销窗口结束后才提交、队列不受店铺范围限制、新店铺自动归位。
- 2026-10-05（待办 07）：保存店铺时已在同一事务里发出「店铺已变更」——任务 `channel.store_changed`，载荷 `{ storeId, addedMailboxes }`（这次新登记的进线邮箱，新增店铺时为全部，地址已转小写），处理器在 `apps/server/src/modules/channel/jobs.ts`（现在只记日志），本待办在这里按收件地址匹配未归属来信并归位。店铺按进线邮箱查找用 `channel.store_mailbox.address`（全表唯一）。「指定店铺」下拉的选项用 `GET /api/channel/store-options`（只列授权店铺）。
- 2026-10-05（待办 08）：08 按「同步的邮箱」识别店铺——同步的都是登记过的进线邮箱，所以还不会出现未归属来信。本待办改为按收件地址（To / Delivered-To，头字段在 `channel.message.headers`）识别，识别不出时 `channel.message.store_id` 为空、不发「来信已接收」（或发了由 `ticket` 进队列，`mergeInbound` 现在对没有店铺的来信只记日志）。注意：工单详情按消息自己的店铺读消息（`channel` 的 `listMessageSummaries` 带店铺范围），指定店铺时要一并回填来信的 `store_id`，否则详情会报「读不到」。另外 R-TK-07 的副本（同一封邮件在别的邮箱已收到，`duplicate_of_id` 不为空）也不识别店铺、`store_id` 为空，未归属队列要排除这些行。示例数据里的两封未归属来信（Tom Harris、Lucía Herrera）可加进 `integration/gmail-replay.ts` 回放。
- 2026-10-05（待办 10）：识别（`channel/recognition.ts` 的 `recognizeInbound`）要店铺的平台与默认站点：未归属来信没有店铺，入库时只能按发件域判平台（E-13「平台按发件域判断」，可从 recognition.ts 导出按域判亚马逊与站点的函数复用 `AMAZON_SITE_BY_DOMAIN`）；指定店铺或自动归位时按所归店铺重新跑 `recognizeInbound`（渠道、站点、来源、客户渠道身份）并回填 `channel.message`，再发「来信已接收」。来源规则与店铺无关：未归属的平台通知与营销同样归档、不进队列。非生产环境的「重放来信」（`clearInboundMail`）会一并清掉队列里的来信。

- 2026-10-06（待办 31）：未归属店铺来信进队列时（`channel` 入库的事务里）调 `org` 的 `notifyMembers(tx, { type: 'unassigned_mail', title: '未归属店铺来信', body: 'Tom Harris · amz-ca2@forcome.com 未登记', object: { type: 'message', id: 来信 id, label: 'P04 · 未归属店铺' } })`（原型 G10 的写法；接收人在职客服主管，不传 `storeId`），另发钉钉工作通知给返回的接收人。自动归位用 `unassigned_mail_placed`：这一类按店铺发（`storeScoped`），必须传归位到的店铺 `storeId`，只发给店铺范围包含它的客服主管；原型没画它的标题与说明，写时按 CLAUDE.md 问用户。点通知的去向在 `apps/web/src/lib/notifications.ts` 的 `notificationTargets`：现在两种都到 P04，I17 的队列入口有了地址参数后给 `unassigned_mail` 带上（自动归位到工单详情要等 17）。

- 2026-10-06（待办 05）：未归属店铺来信的通知调 `org` 的 `notifyMembers(tx, { type: 'unassigned_mail', … })` 即可——11.4 渠道里有钉钉的类型由它一并排入钉钉工作通知（同一人 5 分钟内合并），不要另发；「登记新店铺后来信自动归位」（`unassigned_mail_placed`）只发站内。测试写法见 `apps/server/test/work-notifications.int.test.ts`。

- 2026-10-07（待办 14）：指定店铺与自动归位后照样经 `ticket/merge.ts` 的 `mergeInbound` 归并：候选订单号是 `findInboundMessage` 读的时候按来信**当前**所属店铺的平台抽的（`orderNumbers`，不另存列），所以先把 `channel.message.store_id` 与识别结果按所归店铺改好、再发「来信已接收」即可，订单关联、邮箱反查、Shopify 按收件国家定站点都会按新店铺做（R-ST-02「重新识别站点、关联订单并归并」）。归并要的店铺对象取 `channel` 的 `findOrderStore`；补拉订单可能失败重试，最后一次尝试不关联订单照常建单（`JobContext.lastAttempt`，ADR 0008 待办 14 修订）。
- 2026-10-07（待办 16）：指定店铺与自动归位后经 `mergeInbound` 归并时，SLA 列按来信的原到达时间写（`ticket/sla.ts` 的 `inboundSlaColumns`：截止 = `received_at` + 24 小时，归并时已过截止的直接记未达标），不用另外处理；归并还会顺带找等着这封来信的我方回复（`retryWaitingReplies`，回复先于来信入库时记在 `ticket.pending_reply`，最多等 24 小时）。队列里还没归并的来信要显示 SLA 时用 `contracts` 的 `slaDueAt`、`slaRemainingWords`，目标按发件域（亚马逊域为 `platform`，其余 `internal`，同 `slaTargetOf` 的口径）。注意：回复只归到发件邮箱所属店铺的工单（`ticket/replies.ts`），来信被指定到别的店铺时，从原邮箱发出的回复不会归到它。
