**关键取舍**

- **视图放在 `aftersales`、承担算在应用层**（ADR 0005、0006 修订）：视图只放售后成本的口径（P17 只要它），承担金额用 `contracts` 的 `costShares` 逐行算，前后端与导出同一条规则；视图里不再写一份 SQL 版的承担规则，免得两处漂移。
- **合计在应用层求和**：「缺字段」筛选在应用层判断（21 的做法），合计也就对列出的行求和；每行的费用合计取视图，合计行为各行之和（R-AS-08），P17 对同一视图按责任类型求和，两处一致。
- **默认本月由接口按服务端时钟给出**：前端不自己算「今天」——演示的 `CLOCK_START`、测试的手动时钟都跟着走，截图能对上原型的「2026-09-01 至 09-11」。没给的一端取本月的那一端；响应 `range` 写这次按的起止、`defaultRange` 写本月，界面据它判断是否默认（选回本月时地址栏不写起止、不出「清除筛选」）。代价是「全部日期」要显式给起止，界面不需要；报表下钻（25）带起止。
- **导出与列表同一份数据**：`exportLedger` 调 `listLedger`，再 `stripFinanceFields` 去掉坐席不该看的字段、按权限取列；导出的列不随列设置变化（导出的是「当前筛选」的完整台账，用户确认 ⑦）。被拒（403、400）不记导出审计。
- **审计动作 `ledger.export`**（对象.动词）、对象类型「导出」、对象「登记台账」，后值写文件名、筛选条件（含这次的起止）、行数与是否含财务字段；跨店铺导出的店铺为空——P27 按 10.2 的过滤随待办 30 一并考虑（受限的客服主管能否看到这类记录）。
- **地址栏的 `?missing=1`**：TanStack Router 把手写的 `1` 解析成数字，原来的 `z.literal('1')` 会把它丢掉（21 的界面跳转写的是字符串 `"1"`，所以之前没暴露）；改为 `z.coerce.string().pipe(z.literal('1'))`，报表下钻手写的地址也认。
- **e2e 与示例数据**：示例台账在 2026 年 9 月、台账默认只列本月，已有 e2e 看示例单时带上 `?from=2026-09-01&to=2026-09-30`；新用例的数字只核对列表与文件、合计行与各行之间的关系，开发测试环境数据累积也能重复跑。
- **Node 24**：照 README「开发」与待办 01 的做法，便携 Node 24.21.0 只在会话内前置 PATH，pnpm 10.34.6 经 corepack。

**自己写而没用现成库的部分**

- 下载：浏览器内存里的 Blob 用对象地址 + `a[download]` 触发保存（`lib/download.ts`，十来行），不引 file-saver。
- 合计与承担：big.js（已有依赖）做十进制运算，没有引入金额库；列设置的本机存储十来行（localStorage + try/catch），没引状态持久化库。
- 用到的现成库：exceljs（规格指定）生成 Excel；TanStack Table（ADR 0007 的技术栈、设计规范「表格 → TanStack Table：列显隐」）管列定义与显隐；cmdk（shadcn Command，设计规范「筛选器为 Popover 内的 Command 列表」）；DayPicker 的区间模式做区间日历；e2e 用 exceljs 读下载的文件。

**组件库带来的细微视觉差异**（由我定，汇总给用户过目）

- FSH / 工厂承担的悬停用原生 `title`（与原型页面 `p1_share()` 一致，P13 的「缺 N 项」、汇率说明同此写法）：三组不同时浏览器原生悬停是多行纯文字，「按费用项」不加粗（状态板上的深色气泡是示意）。已取消单没保留项的悬停同理。
- 合计行固定在表格滚动区底部、表头固定在顶部：数据多到放不下时表格在自己的区域里纵向滚动，页面本身不滚；列多时整表横向滚动，被首列盖住的列露出一截（例如责任徽标的尾巴，见 `22-all-columns-scrolled.png`），原型没画滚动中的样子。
- 「列设置」菜单用 shadcn DropdownMenu 的勾选项（原型 `checkbox()` 同尺寸），关闭后焦点回到「列设置」按钮，显示组件默认的焦点环。
