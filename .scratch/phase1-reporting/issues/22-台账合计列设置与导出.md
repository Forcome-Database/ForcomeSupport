# 22: 台账合计、列设置与导出

Status: ready-for-agent
Blocked by: 20, 21

规格：[第一期：报表与台账](../spec.md)

**What to build:** P13 成为可交付的台账，按 PRD P13「第一阶段」小节与状态 S13。筛选：日期（按费用发生日）、店铺、处理方式、责任、状态、负责人。列：售后单号（带「缺 N 项」）· 客户 · 店铺与站点 · 处理方式 · 责任 · 状态 · 负责人 · 生产厂 · 配件 × 数量 · 快递单号 · 产品成本 · 运费 · 额外赔偿 · 其他 · 费用合计 · FSH 承担 $ · 工厂承担 $；默认隐藏 配件 × 数量、负责人、其他、生产厂（生产厂是 R-AS-08 必填字段，缺失时计入「缺 N 项」）。FSH 承担 $、工厂承担 $ 按 R-AS-08 计算（工厂承担逐行四舍五入到分，FSH 承担 = 该行费用合计 − 工厂承担），悬停显示三组比例，三组相同写一个值、不同写「按费用项」可展开，第一期不带「≈」；金额旁显示原币与汇率日期（例「MX$889.00 · 汇率 09-10」）。合计行（产品成本、运费、额外赔偿、其他、费用合计、FSH 承担、工厂承担），首列与合计行在横向滚动时固定；合计行下没有结算拆解。合计来自一个**售后成本 SQL 视图**（R-AS-08：非待确认单的已登记费用，已取消的单只计确认保留的部分，按费用发生日归期），此视图将被报表复用（AC-RP-01）。「列设置」显示或隐藏列。「导出 Excel」：服务端 exceljs 按当前筛选与字段权限同步生成后直接下载，不留存文件，记审计（S11、K5）。不显示「售后单」「内部结算」页签、报备 / 协商 / 结算列与筛选、「✦ 积加有单号」预填。

- [ ] 单元测试：承担金额计算（三组相同与不同两种；逐行取整后 FSH + 工厂 = 费用合计）
- [ ] 集成测试：用示例夹具（`p1_ledger_rows()`，丢弃待确认单，固定演示汇率），合计行费用合计为 $188.79，FSH $58.85、工厂 $129.94
- [ ] 集成测试：已取消单只计确认保留的费用；行内按保留部分显示各费用项与承担额，原登记额在悬停中，合计行等于各行之和
- [ ] 集成测试：坐席导出的文件不含七个金额列；导出写审计
- [ ] 集成测试：店铺范围过滤作用在视图查询上
- [ ] Playwright：筛选 → 导出 → 下载文件行数与列表一致
