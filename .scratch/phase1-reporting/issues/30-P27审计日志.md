# 30: P27 审计日志

Status: resolved
Blocked by: 04, 19, 21

规格：[第一期：报表与台账](../spec.md)

**What to build:** 每个人都能查到操作记录，按 PRD P27 与状态 K18。独立页面，所有角色从顶栏头像菜单「审计日志」进入，管理员另可从 P18 页头进入。筛选：时间（今天 · 近 7 天 · 自定义）、操作人、对象类型（工单、来信、售后单、店铺、渠道、成员、设置、导出、登录；审批单随第二期，PRD P27「第一阶段」）、动作、对象编号搜索，条件写在地址栏。表格：时间 · 操作人（姓名 + 角色；系统操作写「系统」）· 对象（可点进详情）· 动作 · 变更摘要（「字段：前 → 后」）· 来源 IP；行可展开两栏对照完整前后值；越权访问（E-24）记为「越权访问被拒」并红色标。可见范围（PRD 10.2）：客服主管、管理员看全部；其他角色只看自己的操作，页头写「你只能看到自己的操作记录」，操作人筛选锁定为本人；没有财务权限的角色，成本、承担比例、结算金额的前后值显示「已隐藏」（用待办 04 的财务字段过滤工具）。导出按当前筛选同步生成并记审计。

**关键取舍**

- **动作登记表 + 类型化的 `recordAudit`**：P27 要按结构把前后值写成中文并过滤财务字段（`maskFinanceFields` 对没声明的键不放行），快照结构就是唯一依据；写审计时按登记表检查类型，新增动作忘了登记编译不过，没登记的动作在 P27 不显示任何值（失败封闭）。`core` 自己的测试与测试工具自测里原来用的示范动作名改成登记过的动作。
- **写法放在 `contracts`，后端写好再给前端**：页面与导出要同一份写法（导出在服务端），所以 `describeAuditRecord` 在后端调用，接口给的是写好的摘要与两栏的值；前端只负责样式。财务字段在后端换成「已隐藏」，接口与导出里都没有原值（集成测试断言 JSON 里没有金额与比例）。
- **接口放在 `org`、查询放在 `core`**：查看范围取决于访问上下文（角色、店铺范围、财务权限）。`org` 不能依赖 `channel`（`channel` 依赖 `org`），店铺名由组装根注入（ADR 0005 修订）。
- **「动作」筛选写键不写叫法**：地址栏、接口与导出记录里都是 `export`、`aftersales.complete` 这样的键，改叫法不影响旧链接与导出记录。
- **越权店铺写店铺名**：评审发现搜店铺名搜不到越权记录（对象名为空、显示时才补名字）；改为写入时写店铺名，取名函数只在越权时调用，放行的请求不多查一次。较早没写名字的记录显示时仍按 ID 补上。
- **时区与区间**：日期区间按北京时间 0 点左闭右开（`startOfBusinessDate`），今天按服务端时钟（接口返回 `today`），演示的 `CLOCK_START` 与测试的手动时钟都跟着走。
- **表格照 `ledger-table.tsx` 用 TanStack Table**（评审意见）：行展开用 `rowExpandingFeature`，展开状态由页面受控（同一时间只展开一行，改筛选时收起）。
- **Node 24**：照 README「开发」，便携 Node 24.21.0 复制到本会话临时目录、只在会话命令里前置 PATH，pnpm 10.34.6 经 corepack（`--install-directory` 指到该目录）；没有改系统配置。
- **本机内存**：评审修复后的全量 e2e 第一次在后台跑到 48 通过时被 Claude Code 因系统内存不足停掉（本机空闲 3.7 GB / 64 GB，其他项目占用），最后 2 条是 Chromium 崩溃而非用例失败；按协调者决定改为前台逐项串行（单 worker、跑前看空闲内存、跑完确认 4516–4519 没有残留），之后全部通过。
