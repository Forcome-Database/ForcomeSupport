# 16: 回复识别、SLA 与自动关闭

Status: claimed
Blocked by: 09, 10, 14

规格：[第一期：报表与台账](../spec.md)

**What to build:** 工单按第一期生命周期自己走完：我方回了就转「等客户」，再来信回「待回复」，没人理就按时关闭，每封应回复来信都有 SLA 结果。把「已发送」同步到的我方发信，按 `In-Reply-To`、`References`、Gmail 线程的顺序归到工单；回复先于它所回复的来信入库时延后重试（最长 24 小时），来信归并后再归属；晚到的来信若早于已归属的回复，按 `internalDate` 判为已被该回复结束计时。带 `Auto-Submitted` 或自动回复标记的我方邮件不算回复，消息照常入库并标「自动回复」。一封回复结束它之前该工单内所有未回复应回复来信的计时（R-SL-08）。补齐迁移表（照 PRD 6.1 第一阶段迁移表）：待回复 → 等客户（识别到我方回复，且该回复之后没有未回复来信）；等客户 / 已解决 → 待回复（新来信，不论来源）；等客户 7 天无来信 → 已关闭（「客户未回复」）；已解决 7 天无来信 → 已关闭（「已解决后无来信」）；待回复 14 天无新来信 → 已关闭（「未识别到回复」，其中的应回复来信 SLA 计未达标）。每分钟扫描任务（接收显式当前时间），7 天、14 天都从工单内最近一封来信的到达时间起算（PRD 6.1）。每封应回复来信保存到达时间、SLA 截止（亚马逊 24 自然小时，Shopify 与邮件内部目标 24 小时，第一期固定）、首次回复时间、SLA 结果（达标 / 未达标 / 未到期 / 无需回复）；生产厂与其他供应商来信不计。每次迁移写状态变更记录（时间、事件、触发方），工单存关闭原因。工单量所需的「由客户来信触发的新建与重开事件」在这里记录。第一期不产生 SLA 提醒。
