# 04: 角色、店铺范围与导航

Status: ready-for-agent
Blocked by: 02

规格：[第一期：报表与台账](../spec.md)

**What to build:** 用开发登录以任一角色进入系统时，只看到自己该看到的东西。服务端会话（PostgreSQL 存储，httpOnly、Secure，无操作 7 天过期）；6 个固定角色（坐席、客服主管、售后负责人、知识库负责人、管理员、生产厂对接人）。能力矩阵按 PRD 10.1 的细粒度能力写成 `contracts` 常量，每项标注上线阶段（第一期新增：标记来信无需回复、为未归属来信指定店铺、新建与编辑登记、设为已完成、补登与修改汇率、改派售后单负责人、查看财务字段、查看审计日志 P27），前端据此显示、后端据此强制；多角色权限取并集。店铺数据范围作为所有仓储查询的必需上下文参数（缺了编译不过，ADR 0010）。提供财务字段过滤工具（成本、承担比例、承担金额只对客服主管、售后负责人返回），供后续接口、导出、下钻与审计输出复用。外壳按 PRD 4.1 第一阶段表：导航与默认首页按角色（多角色导航取并集，默认首页按 坐席/客服主管 → 售后负责人 → 知识库负责人/管理员 取第一个）；顶栏不显示店铺切换、全局搜索与导航角标；头像菜单含「审计日志」「密度」「退出登录」。只有生产厂对接人角色的成员第一期登录返回无权限（G12）。直接访问无权页面显示 G2（按钮「返回首页」），越权访问写审计（E-24）。顶栏密度切换（舒适 / 紧凑），偏好存服务端。

- [ ] 集成测试：坐席、客服主管、售后负责人、知识库负责人、管理员各自登录后的默认首页与导航入口与 PRD 4.1 第一阶段表一致；多角色成员导航取并集
- [ ] 集成测试：只有生产厂对接人角色的成员登录被拒（AC-P1-21）
- [ ] 集成测试：带越权店铺 ID 的请求被拒绝并写审计
- [ ] 集成测试：财务字段过滤工具对无权角色去掉字段，对客服主管、售后负责人保留
- [ ] 单元测试：能力矩阵常量覆盖 PRD 10.1 全部能力行，第一期能力标为已上线
- [ ] 坐席访问设置页链接显示无权限，按钮只有「返回首页」（AC-ST-03、G2）
- [ ] 密度切到紧凑后刷新与重新登录都保持（AC-ST-04），按设计规范第 12 节两套 CSS 变量切换
- [ ] 会话 7 天无操作过期（用可注入时钟测试）
