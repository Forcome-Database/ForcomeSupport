# 04: 角色、店铺范围与导航

Status: ready-for-agent
Blocked by: 02

规格：[第一期：报表与台账](../spec.md)

**What to build:** 用开发登录以任一角色进入系统时，只看到自己该看到的东西。服务端会话（PostgreSQL 存储，httpOnly、Secure，无操作 7 天过期）；6 个固定角色，PRD 10.1 能力矩阵作为 `contracts` 常量，前端据此显示、后端据此强制；多角色权限取并集。店铺数据范围作为所有仓储查询的必需上下文参数（缺了编译不过，ADR 0010）。提供财务字段过滤工具（成本、承担比例、承担金额只对客服主管、售后负责人返回），供后续接口复用。按角色的默认首页（坐席与客服主管 P04、售后负责人 P13、知识库负责人与管理员 P17；多角色按 坐席/客服主管 → 售后负责人 → 知识库负责人/管理员 取第一个），导航只显示第一期存在且有权的入口；直接访问无权页面显示 G2，越权访问写审计（E-24）。顶栏密度切换（舒适 / 紧凑），偏好存服务端。

- [ ] 集成测试：6 个角色各自登录后拿到的默认首页与导航入口正确
- [ ] 集成测试：带越权店铺 ID 的请求被拒绝并写审计
- [ ] 集成测试：财务字段过滤工具对无权角色去掉字段，对客服主管、售后负责人保留
- [ ] 坐席访问设置页链接显示无权限（AC-ST-03）
- [ ] 密度切到紧凑后刷新与重新登录都保持（AC-ST-04），按设计规范第 12 节两套 CSS 变量切换
- [ ] 会话 7 天无操作过期（用可注入时钟测试）
