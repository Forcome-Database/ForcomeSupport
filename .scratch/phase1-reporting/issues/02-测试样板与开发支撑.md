# 02: 测试样板与开发支撑

Status: resolved
Blocked by: 01

规格：[第一期：报表与台账](../spec.md)

**What to build:** 让之后每张待办都能按同一个样板写测试、在没有任何外部账号的情况下端到端开发。建立规格中确认的**主接缝**测试工具：在测试进程内直接调用 Hono 应用、使用真实 PostgreSQL、以指定角色登录、注入 Fake 外部客户端、推进可注入时钟、同步把 worker 任务跑到空闲。建立 Fake 框架（每个外部客户端一个 Fake，可模拟成功、失败、超时、游标过期、断线恢复；按店铺配置选择真实或 Fake）。提供只在非生产环境由环境变量开启的开发登录。把原型示例数据 `design/spec/data.py` 转成 JSON 夹具，并提供加载器，供种子数据、Fake 回放与 Playwright 共用。转换规则（第一期）：工单取 `p1_tickets()`（第一期状态与补充工单）；台账取 `p1_ledger_rows()`（丢弃待确认的单，带 `LEDGER_EXTRA` 的登记字段）；P05 时间线取 `P1_OLIVER`；Fake 汇率固定为演示汇率 1 USD = 18.00 MXN、1.36 CAD，保证 $188.79 等按原型数据验收的数字可复现；第一期台账行的创建路径一律记为「手工登记」，登记人取负责人（原型的 `reg` 字段不转换）。加载器只提供可扩展的框架：各模块建表后在自己的待办里注册加载步骤（工单在 08、台账在 19）。前端提供登录后的空顶栏外壳。

- [x] 一个示范集成用例：开发登录 → 调用一个受保护接口 → 断言审计里有登录记录；用例只经主接缝，不碰内部函数
- [x] 测试工具支持：按角色建会话、推进时钟、「跑完所有已排队任务」、重置 Fake 状态
- [x] Fake 框架提供注册与按店铺选择机制，含一个示范 Fake 的故障注入测试

**关键取舍**

- 会话的边界（02 与 04）：开发登录必须换出真正的会话（05「扫码登录换出与开发登录同一种会话」），所以 02 建了会话表与 `requireSession`，但不建成员表、不定角色枚举：会话行先存登录时的姓名与角色快照，04 号待办引入成员表后改为引用成员、实时读角色，并加 7 天无操作过期、续期与退出登录（`last_active_at` 已留）。开发登录的成员取自夹具，id 是从 key 派生的 UUIDv5，04 灌成员表时沿用同一组 id，已开的会话不失效。
- 「生产构建中开发登录不可用」按运行环境落实：后端只有一个镜像（开发测试环境的冒烟要用开发登录），无法靠分开构建。生产环境配置 `DEV_LOGIN_ENABLED=true` 拒绝启动，接口层再判断一次、不挂 `/api/dev/*`（OpenAPI 里也没有），`getDemoFixture()` 懒加载使生产进程不解析夹具；前端开发登录页只在后端提供成员列表时出现。已回写规格与 ADR 0010 修订。
- 开发登录不列生产厂对接人（陈工、张工）：PRD 4.1「第一阶段不分配此角色；已分配者登录显示无权限（G12）」，02 没有角色模型，列出来就会让他们进入外壳；04 号待办实现登录被拒（AC-P1-21）时连同这两位一起加回来。
- 全局客户端的选择用 `CLIENT_MODE_<系统>`（不用 `<系统>_CLIENT`：会和 `SSH_CLIENT` 之类的系统变量撞上）；不设时非生产用 Fake、生产用真实现；`IntegrationClients` 构造时拒绝没登记或店铺级的系统名，防止拼错后悄悄用了 Fake。
- 「跑完任务」不管 `startAfter`（测试时间由手动时钟控制），失败的任务本次不重试、跑完才交给 pg-boss，这样「回复先到、来信归并后重试成功」能分两次 `runJobs` 写出来；不跑 cron，定时扫描用 `t.enqueue` 显式排。pg-boss 12 的 `fetch` 自带 `ignoreStartAfter`，没有碰它的内部表。
- 示范 Fake 放在测试文件里，没有在生产代码里放一个假的外部系统；各集成（05、08/09、11、12、20）照它定义自己的客户端。
- 夹具只转换规则点名的数据与被引用的参照数据（成员、店铺、生产厂、配件、责任默认比例），业务取值保留中文；订单、未归属来信等由需要的待办在生成脚本里补规则。生成脚本二进制写出 LF，`fixtures:verify` 逐字节比较；产物不归 prettier 管。
- 前端调接口用 `fetch` + `contracts` 的 zod 模式，不用 ADR 0006 写的 `hono/client`：它要从前端引用后端的应用类型，与 01 定下的「前端不引用后端代码」边界冲突（写入 ADR 0006、0007 修订）。
- 本机端口：开发 api 4516、前端 4517，e2e api 4518、前端预览 4519，4510–4515 留给 03（ADR 0013 修订）；本机默认环境变量放 `dev.env` 并用 Node 的 `--env-file`，免去手设 `DATABASE_URL`。
- Node 24：照 README「开发」与待办 01 的做法，把便携 Node 24.21.0 放在本会话的临时目录、只在会话命令里前置 PATH，pnpm 10.34.6 经 corepack 取用；Playwright 1.63 用本机已缓存的 Chromium 1243，没有下载浏览器。

**自己写而没用现成库的部分**

- 进程内 HTTP 客户端的 Cookie 处理（`test/api-client.ts`，约 30 行）：tough-cookie 之类要按域名与 URL 匹配，进程内请求没有真实域名；这里只需原样回送响应里的 Cookie。
- 故障注入 `FaultInjector`（约 80 行）：nock、msw 拦的是 HTTP 层，Fake 不发 HTTP；Gmail、钉钉 Stream、SQS 的 Fake 都要按「操作」注入失败、超时、游标过期与断线，与传输层无关。
- 「跑完任务」`test/run-jobs.ts`（约 80 行）：pg-boss 自带的 `work()` 是轮询式的、跑不到「空闲」就返回；用它的 `fetch`、`complete`、`fail` 组合出同步排空。
- 加载步骤的依赖排序（`core/fixtures.ts` 的 `ordered`，约 30 行）：只有几个步骤，按层排序加循环检测，引一个拓扑排序库不划算。
- 夹具生成脚本（Python）：示例数据本身是 Python（`data.py` 的函数），直接导入调用最可靠。
