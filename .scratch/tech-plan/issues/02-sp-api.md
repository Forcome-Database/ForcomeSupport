# 调研：亚马逊 SP-API 退款、取消、读订单与开发者资质

## Question

PRD Q-23 定了「亚马逊退款、取消经 SP-API 执行」，这个前提是否成立？

需要查清：
- 自发货（MFN）订单的退款：是否有直接 API；若只能经 Feeds（订单调整 `POST_PAYMENT_ADJUSTMENT_DATA` 或 JSON 等价物）提交，写明流程、时延、结果回执方式。
- 取消订单：取消买家请求、卖家主动取消的接口方式。
- 部分退款（部分补偿）与全额退款的支持情况。
- 读订单与买家信息所需角色，受限数据（PII）的申请要求、数据保护政策（加密、存储、留存期限、审计）对部署方式的约束，尤其是否允许存放在中国大陆服务器。
- 开发者注册流程（私有应用 vs 公开应用）、所需资料、周期。
- 买家消息：确认 Messaging API 不能读来信，官方沟通方式为邮件中转（PRD D-14 的依据）。

## Answer

详见分支 `research/sp-api`（提交 0a93b11）的 `docs/research/亚马逊SP-API.md`，含 10 项待确认，来源访问日期均为 2026-09-24。

- **退款**：没有直接退款接口，只能提交订单调整 feed（`POST_PAYMENT_ADJUSTMENT_DATA`，XML）；可按商品行全额或部分退款，调整原因 18 种；订单须已确认发货；处理最长约 8 小时，成败逐条看处理报告。
- **取消**：订单确认 feed（`POST_ORDER_ACKNOWLEDGEMENT_DATA`，状态 `Failure` + 取消原因）；只能取消未确认发货的订单，不支持部分取消。
- **买家取消请求**：从订单接口的取消标记或 `ORDER_CHANGE` 通知识别；买家走正式「请求取消」流程、以「买家取消」为原因执行，才不计入取消率。
- **改地址**：亚马逊不允许卖家改地址，只能请买家取消后重新下单。P22「平台不支持」正确，但悬停说明「坐席在卖家后台人工处理」不成立，需改。
- **读订单**：旧版订单接口 2027-03-27 下线；按 D-17 订单走积加，可只申请非受限角色，不接买家个人信息接口，免去额外数据安全评估。
- **开发者资质**：注册私有开发者，由店铺主账号自授权；一次北美授权覆盖美、加、墨三站（前提是同一北美统一账户，待确认）；审核周期未公布。
- **买家消息**：Messaging API 不能读来信也不能自由回复；邮件中转 + Gmail 可行，但 Gmail 发件地址须先在卖家后台授权，否则拒收；每天发信有上限。
- **数据政策**：DPP、AUP、开发者协议不限制存储地域；硬性要求：买家 PII 订单交付后最多留 30 天、静态加密、全员 MFA、日志留 12 个月、安全事件 24 小时内通报、异地备份、记录全部数据副本位置。

**Q-23 结论**：可行，改为「经 Feeds 异步执行」；执行前按发货状态分流（未确认发货 → 取消，已确认发货 → 退款）；人工操作清单继续兜底（feed 报错或超时、退货授权、重新入库费、A-to-z 申诉）。

**对其他待办与 PRD 的影响**
- PRD 需改：Q-23、R-AP-04、R-AP-05（亚马逊动作为异步，执行中状态可能持续数小时，绑定回复在处理报告成功后才发出）；P22 改地址悬停说明；审批单执行结果需支持异步回执。
- 「讨论：后台任务与流程引擎」：需要 feed 提交 → 轮询处理报告 → 回写结果的长流程。
- 「讨论：部署拓扑与数据合规」：PI 留存 30 天与加密、MFA、日志 12 个月的要求；北美买家数据存大陆是否合规需法务确认（亚马逊政策本身不限地域）。
- 「讨论：集成层设计与「MCP 形式」的含义」：亚马逊适配器以 Feeds 为主，需要异步回执模型。
