# 讨论：AI 处理的编排与治理

## Question

在五步处理（PRD 5.1）与 ADR 0012 的模型接入层之上，AI 处理怎么编排与治理？只定架构，不细化到提示词。

要定（依据「调研：电商客服 AI 工作流与模型应用」第 2–8 节）：
- **意图流程**：12 条 R-IN 是否升级为「结构化字段 + 客服主管维护的自然语言说明」，维护入口（P19 还是知识库）、版本与发布门槛（回归样例），对应 U-02。
- **上下文装配**：按意图预取哪些数据、装配顺序与缓存前缀、知识过滤与是否全量放入（U-01）、对话历史与客户历史摘要的截断、买家来信的不可信输入隔离。
- **治理**：动作前置条件与允许集合、R-CK 五项里规则与模型的分工、事实与承诺的证据编号核对、「疑似提示注入」风险信号（U-04）、自动发送放开前的回归门槛。
- **意图与情绪**：来源类别字段、置信度改为可复算的综合分并与 R-SD、R-KB-04 对齐（U-03）、升级风险逐项输出加证据、关键词与模型的分工。
- **草稿**：默认 3 版是否保留（U-05）、换一版与中文修改回译的调用方式。
- **评测闭环**：回归集来源（Q-08 样本、被拒草稿）、打分细则与人工校准、CI 门控、线上采纳率反馈。
- **范围**：全量质量分与话题洞察是否纳入（U-13）。

涉及 PRD 新增或修改的，记入地图的 PRD 回写清单。

## Answer

2026-09-24 用户同意全部推荐，详见 ADR [0014 AI 处理为固定流水线加意图流程与代码治理](../../../docs/adr/0014-AI处理为固定流水线加意图流程与代码治理.md)。

- **工作流**：五步流水线；第三期不上智能体，`draft` 不开放工具，数据由代码预取。
- **意图流程**：结构化部分由代码执行，自然语言说明在 P19 新增的「处理说明」页签由客服主管维护；带版本，发布前跑回归。
- **上下文**：7 段固定顺序，前 3 段可缓存；知识过滤后放得下就全部放入，否则用 pgvector 检索；来信作为不可信内容隔离。
- **治理**：动作只能取允许的枚举、前置条件由代码判定；R-CK 以规则和代码为主；承诺与审批项双向对账；新增「疑似提示注入」；放开自动发送前回归集须连续 5 次全部通过。
- **意图与情绪**：来源类别；可复算的置信度；每封新来信都重新判定；一致率 ≥ 95%；风险逐项带证据，关键词与模型取并集；新增紧急度。
- **草稿**：一次调用生成 3 版，「换一版」单独调用。
- **评测**：500 封样本 + 被拒草稿做回归集；judge 打分先与人工对齐；任何变更先跑回归；线上监控与每周修改汇总。
