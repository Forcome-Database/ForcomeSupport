# 讨论：第一期报表的数据来源与同步

## Question

第一期报表与台账的数据从哪来、怎么同步？

要定：工单量、首次回复与 SLA（按邮箱收发时间，Q-26）、售后成本（台账）的数据来源；积加订单与物流的同步方式（全量、增量、频率）；报表计算放在业务库还是独立的汇总表；T+0、15 分钟内的时效（PRD 1.2）如何保证；历史数据导入（近 90 天工单与售后登记表，第 14 节）。

## Answer

2026-09-24 用户同意全部推荐。订单来源见 ADR [0011 订单读取改为平台直读](../../../docs/adr/0011-订单读取改为平台直读.md)。

- **订单来源**：亚马逊走 SP-API v2026-01-01 非受限角色（`ORDER_CHANGE` → SQS 长轮询 + 每 3～5 分钟增量兜底）；Shopify 走 Admin API（每 1～2 分钟增量）；亚马逊买家姓名与地址、补发、库存、运费仍走积加。不换领星。需开 AWS 账户。
- **`order` 模块**：本地订单镜像，上线时回补 90 天，每天夜间对账，以平台订单号为关联键；积加只补充收件人与履约。
- **第一期页面**：登录、P17 报表、P13 台账（手工登记与补登）、P04 与 P05 只读版、P18、P20。17TRACK 物流轨迹推到第二期，第一期只存单号与承运商。
- **首次回复**（Q-26）：同步 4 个邮箱的「已发送」，按 Gmail 线程与 `In-Reply-To`、`References` 反推；报表注明只统计经店铺邮箱发出的回复。
- **报表**：直接查业务表（SQL 视图 + 索引），「更新于」显示各数据源最近一次同步成功的时间；以后变慢再改物化视图。
- **台账**：每一行就是一张售后单（同一张表），创建路径为「手工登记」，状态先用简化版。
- **历史导入**：近 90 天邮件走线上同一条流程，标记「历史」、不触发 SLA 提醒；售后登记表用一次性命令行导入，映射表拿到真实表格后再定；订单回补 90 天。
- **导出**：服务端 exceljs 同步生成，每次导出记入审计。
