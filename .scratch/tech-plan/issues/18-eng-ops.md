# 讨论：工程与运维

## Question

在 ADR 0003 的拓扑（大陆公司服务器、Docker Compose、生产与开发测试两套环境、每日备份）之上，工程与运维怎么做？

要定：CI/CD（代码托管在哪、构建与镜像仓库、AI 代理按待办实现的代码如何经开发测试环境再上生产、数据库迁移怎么执行）；监控告警（应用、队列积压、外部接口失败、积加与 17TRACK 额度，告警发到钉钉的方式与钉钉标准版配额的冲突）；日志收集与查询；密钥管理（Shopify 24 小时令牌刷新、Google 服务账号、SP-API 凭证、NewAPI 密钥放在哪、怎么轮换）；备份任务的具体实现与恢复演练流程。

## Answer

2026-09-24 用户同意全部推荐，详见 ADR [0013 GitHub 托管与内网自托管运行器部署](../../../docs/adr/0013-GitHub托管与内网自托管运行器部署.md)。

- **CI/CD**：GitHub 私有仓库 + Actions；部署由内网自托管运行器执行；main 自动部署开发测试环境，打标签并人工批准后部署生产。
- **门槛**：类型检查、lint（含边界）、单元测试、集成测试（真实 PG + Fake）、1 人评审；合并后跑 Playwright。
- **迁移**：只向前；生产迁移前备份；破坏性变更分两次发版。
- **监控**：先确认运维现状，没有就用 worker 自检 + 钉钉群机器人 + 「系统状态」页。
- **日志**：pino JSON + Docker 轮转，保留 30 天。
- **密钥**：静态密钥放 `.env`；动态凭据 AES-GCM 加密存库；不用 Vault。
- **备份**：pg_dump + 附件卷，restic 同步到 NAS，保留 30 份日备份与 12 份月备份，每季度演练。
- **环境**：开发测试与生产同机、各自独立；本机开发全部用 Fake。
- **待确认**：运维现有的监控与日志系统；GitHub 相关域名的代理放行。
