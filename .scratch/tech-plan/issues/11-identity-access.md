# 讨论：身份与权限

## Question

登录、角色权限、店铺数据范围和审计怎么实现？

要定：钉钉扫码登录与钉钉内免登的会话方式；通讯录同步（每小时 + 变更事件）与成员停用（D-16）；角色与能力矩阵（PRD 10.1）的建模；店铺数据范围在查询层的强制方式（后端校验，不依赖前端）；生产厂对接人的数据隔离（R-FT-02）；审计日志的写入点与查询。

## Answer

2026-09-24 用户同意全部推荐，详见 ADR [0010 会话在服务端与权限在应用层强制](../../../docs/adr/0010-会话在服务端与权限在应用层强制.md)。

- **会话**：PostgreSQL 服务端会话 + httpOnly Cookie，无操作 7 天过期；扫码与免登换出同一种会话；主应用与工厂 Cookie 各自独立。
- **同步与停用**：Stream 事件 + 每小时对账；停用时立即失效会话、释放锁，负责的对象转「待分配」，通知主管或管理员。
- **角色**：6 个固定角色，能力矩阵是 contracts 中的常量，前后端共用；可多角色，权限取并集。
- **店铺范围**：仓储查询强制带范围上下文 + 越权测试；不用 RLS。
- **生产厂**：`/api/factory/*` 专用输出结构，生产厂 ID 只取自会话；保留「寄件完成 30 天后对生产厂隐藏」。
- **审计**：写操作、登录登出、强制接手、导出都记；按 PRD 10.2 控制可见范围。
- **钉钉通知**：内容带编号与时间、5 分钟合并、配额监控。
- **待确认**：集团钉钉版本（标准版、专业版还是专属版）。
