# 调研：Gmail、Shopify Admin API 与钉钉开放平台的能力与限制

## Question

三个已有管理权限的平台，实际能力与限制各是什么？

需要查清：
- **Gmail API**：推送（Pub/Sub watch）与轮询；按店铺邮箱收信；收发亚马逊买家消息中转邮件（发往中转地址的限制：附件、链接、HTML）；发信配额；服务账号 + 域委派的授权方式。
- **Shopify Admin API**：退款（含部分退款）、改收货地址、取消订单、订单备注的接口（GraphQL 优先）；自定义应用的创建方式、权限范围、频率限制；多店铺时的凭据管理。
- **钉钉开放平台**：企业内部应用；通讯录同步（成员、部门、变更事件）、工作通知、扫码登录与钉钉内免登；频率限制；需要集团管理员开通的权限清单。
- 三者在「私有化部署、经代理访问」下的要求（回调地址是否必须公网可达，如 Gmail Pub/Sub、钉钉事件订阅）。

## Answer

详见分支 `research/gmail-shopify-dingtalk`（提交 5e28165）的 `docs/research/Gmail-Shopify-钉钉.md`，含 10 项待确认（客户钉钉版本、邮箱是否真实用户、两个 Shopify 店铺是否同一组织等）。

- **Gmail**：收信用 Pub/Sub pull 订阅由系统主动拉取（push 订阅需公网 HTTPS，不可用），`history.list` 定时轮询兜底；授权用服务账号 + 全域委派逐个模拟 4 个邮箱；发信上限每邮箱每天 2,000 封。
- **亚马逊回信**：必须从卖家平台注册或已批准的邮箱发出，否则被拒；外部链接、附件、邮箱地址、电话、表情受限，整封 ≤ 10 MB（与 PRD R-CC、R-CK 一致，需在回复检查中落实）。
- **Shopify**：后台已不能新建旧式自建应用，改在 Dev Dashboard 创建，令牌 24 小时过期需刷新；`refundCreate` 自 2026-04 版起必须带幂等键；Webhook 可投递到 Pub/Sub 再拉取；第一期订单读取走积加，可不订 Webhook。
- **钉钉**：通讯录变更用 Stream 长连接（系统主动连出，内网可用），HTTP 推送需公网地址；扫码登录回调是浏览器跳转，用内网域名即可。

**内网部署的关键限制**
1. 钉钉内免登要求手机能打开系统页面：工厂人员在厂外或用 4G 时需要公网入口、VPN 或零信任网关（P21 工厂工作台手机端、F9）。
2. 钉钉标准版配额：每月 API 调用 5,000 次、事件推送 3,000 次；工作通知计入额度（通讯录读取与登录不计）；同一员工一天只收到一条内容相同的通知，超出时接口仍返回成功但用户收不到。
3. 大陆部署时 Google 与 Shopify 需经境外代理，钉钉可直连。
4. 钉钉 Stream 能否经公司 HTTP 代理连上，官方未写明，需联调验证。

**对其他待办的影响**
- 「讨论：部署拓扑与数据合规」：要决定工厂工作台手机端的外网访问方式（公网入口 / VPN / 零信任）。
- 「讨论：身份与权限」：钉钉配额与同内容通知去重会影响审批提醒、生产厂催办（R-AP-03、R-FT-05）的通知设计，需确认客户钉钉版本。
- 「讨论：集成层设计与「MCP 形式」的含义」：Gmail 用 pull + 轮询；Shopify 令牌 24 小时刷新、退款带幂等键；亚马逊回信的发件邮箱须为已注册邮箱。
