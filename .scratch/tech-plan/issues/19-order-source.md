# 调研：订单数据的准实时来源（SP-API 非受限订单接口、Shopify Admin API、第三方聚合平台）

## Question

2026-09-24 用户了解到：积加开放接口拿到的订单不是实时的，是隔天（T+1），不满足第一期「报表 T+0、15 分钟内」和按订单归并来信（R-TK-01）的需要。用户要求订单改为对接官方接口，或找类似的中间聚合平台；SP-API 的 PII（受限数据）角色很难申请。

要查清：
1. **SP-API 只用非受限角色能拿到哪些订单数据**：新版订单接口（旧版 2027-03-27 下线）与旧版各自的字段；订单状态、商品行、MFN/AFN、发货时间、预计送达、收件城市/州/邮编/国家、**承运商与快递单号**（MFN 由易仓发货、积加回传亚马逊后是否能读到）；按更新时间增量拉取、`ORDER_CHANGE` 通知（经 SQS/EventBridge，能否在内网只出站拉取）、限流与延迟。买家邮箱、姓名、详细地址确定需要受限角色吗？
2. **Shopify Admin API**：订单、客户邮箱、发货单与快递单号；受保护客户数据（protected customer data）对单店自建应用的申请方式；增量拉取与限流。
3. **第三方聚合平台**：有没有能在准实时（≤ 15 分钟）内提供亚马逊（美、加、墨）与 Shopify 订单、发货单号，且对外有开放接口的平台，比如领星、马帮、店小秘、赛盒、ShipStation、Veeqo、Rithum（ChannelAdvisor）、Linnworks 等。要写清同步延迟、开放接口能力、是否能带出买家邮箱与地址（它们作为亚马逊认证服务商本身有 PII 权限）、价格、和积加并存是否冲突。
4. **积加订单的时效**：用户说是隔天，积加调研里写的是「约 1 分钟抓亚马逊、5 分钟同步其他平台」。两者的差别在哪（开放接口与界面的差别？订单与包裹单的差别？），能否向积加确认。

结论要回答：订单读取推荐走哪条路（可以分平台、分字段组合），和 ADR 0002 相比要改什么。参考：「调研：积加开放接口能力与申请方式」「调研：亚马逊 SP-API 退款、取消、读订单与开发者资质」「调研：Gmail、Shopify Admin API 与钉钉开放平台的能力与限制」的结论。

## Answer

详见分支 `research/order-source`（提交 9b2fe52）的 `docs/research/订单实时来源.md`，含待确认 O-1 到 O-9。

- **推荐：按字段拆分来源，不接聚合平台**。
  - 亚马逊订单（状态、商品行、MFN/AFN、承诺时效、城市/州/国家、MFN 快递单号）走 SP-API Orders v2026-01-01，只用非受限角色 Inventory and Order Tracking。退款、取消 feed 本来就要这个角色，读订单不增加申请项。
  - Shopify 订单（含客户邮箱、收件地址、履约单号）走 Admin GraphQL API，与退款共用一个自建应用。
  - 亚马逊买家姓名与街道地址（补发要用）继续取积加订单详情（订购一个月内），取不到时由坐席补填。补发、库存、运费不变。
- **同步（全部只出站）**：亚马逊订阅 `ORDER_CHANGE`，投递到我方 AWS us-east-1 的 SQS 队列，经代理长轮询，另每 3～5 分钟按 `lastUpdatedAfter` 增量兜底（订单查询默认约每 3 分钟 1 次、突发 20 次）；Shopify 每 1～2 分钟增量。能满足「15 分钟内」。需要一个 AWS 账户（SQS 在免费额度内）。
- **非受限角色拿不到**：买家邮箱、姓名、街道、电话；美国站邮编也拿不到（加拿大、墨西哥站可以）。买家邮箱用不上，因为亚马逊来信里已有匿名邮箱与订单号。
- **聚合平台**：只有 Veeqo 能覆盖三站（亚马逊每 10 分钟同步，可返回收件信息），但它会回写平台、同步库存，与积加冲突，只留作备选。领星、马帮是积加的同类 ERP，接入等于换 ERP。ShipStation、Linnworks、Rithum、店小秘、赛盒未取得一手资料。
- **积加时效**：官方文档写亚马逊每 1 分钟、其他平台每 5 分钟同步，和「隔天」对不上。可能慢的是发货单号、运费或统计数据，需向积加确认（O-6）。
- **最大不确定项**：积加回传亚马逊的 MFN 快递单号能否在 v2026-01-01 的 `packages[]` 里读到（O-2）；读不到时单号退回积加取。
- **对 ADR 0002 的影响**：「订单读取｜积加」一行要拆开；积加中断不再影响订单查询。是否采纳在「讨论：第一期报表的数据来源与同步」中决定。
