# 调研：领星能否替代积加

## Question

2026-09-24 用户提出：领星（LingXing）ERP 能否替代积加？

要查清，并与积加逐项对比（积加能力见「调研：积加开放接口能力与申请方式」，订单时效见「调研：订单数据的准实时来源（SP-API 非受限订单接口、Shopify Admin API、第三方聚合平台）」）：

1. **开放接口**：领星开放平台的申请方式、费用、鉴权、限流、IP 白名单；接口目录中订单、发货、库存、运费、售后相关接口。
2. **订单时效**：亚马逊（美、加、墨）与 Shopify 订单进入领星的同步频率，以及经开放接口读取的延迟；能否带出买家姓名、收件地址（领星作为亚马逊服务商的 PII 权限）；能否增量拉取。
3. **易仓对接**：领星是否支持易仓作为三方海外仓（推单、取消、库存同步、出库状态与单号回传、实际运费回传）；经开放接口能否创建补发单（发给买家的售后出库），能否取消。
4. **本系统需要的其他能力**：物流轨迹、退货与退款记录、多店铺、SKU 配对。
5. **切换代价**：价格与套餐；客户若把 ERP 从积加换成领星，数据迁移、并行期、对现有财务与库存口径的影响；领星与积加能否并存（例如只用领星的订单接口）。

结论要回答：领星能替代积加的哪些职责、不能替代哪些；「整体替换 ERP」与「只把领星当补充数据源」两种用法各自是否可行、代价多大；对 ADR 0002 与「调研：订单数据的准实时来源」推荐方案的影响。

## Answer

详见分支 `research/lingxing`（提交 7260b70）的 `docs/research/领星替代积加.md`，含待确认 LX-1 到 LX-8（只有客户考虑换 ERP 时才需要去问）。

- **结论**：不建议用领星替代积加，也不建议把它当补充数据源；ADR 0002 与「调研：订单数据的准实时来源」的推荐方案不用因此修改。
- **开放接口**：超级管理员自助开通，AppID/AppSecret + IP 白名单；限流按「AppId + 接口」算，多数接口并发 1 或 10；接口费用未公开。
- **订单时效**：领星没有公布亚马逊与 Shopify 的同步频率；支持按更新时间增量拉取，不主动推送。
- **关键短板**：接口读不到亚马逊买家姓名与收件地址（积加在订购一个月内可以）；Shopify 订单也没有街道地址。
- **易仓**：两边已对接，但按海外仓逐家对接，FSH 那家是否在名单里待确认。
- **比积加强的地方**：能用接口取消补发单；实际运费约 30 分钟可得；有亚马逊退款接口。物流仍无完整轨迹，仍需 17TRACK。
- **补发**：没有专门的补发单接口，要建手工单再审核；亚马逊店铺能否这样建单待确认。
- **整体换 ERP**：我方只需换适配器；代价主要在客户（店铺、海外仓、SKU 配对、库存、财务口径都要重建），应由客户自己决定。
- **只作补充数据源**：补不上积加的短板，还要多开账号并关掉领星的推单、标发与库存同步，以免重复发货，不划算。
