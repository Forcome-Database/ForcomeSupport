## 5 核心流程

### 5.1 每封来信的五步处理

```
来信 → ① 接收与关联 → ② 风险拦截 →（命中）转人工
                          ↓（未命中）
                     ③ 理解与处理 → ④ 回复检查 → ⑤ 发送方式 → 自动发送 / 待审草稿 / 转人工
                                                                  ↓（草稿含审批项）
                                              坐席审阅 → 提交审批 → 待审批
```

第 ⑤ 步只输出三种结果：自动发送、待审草稿、转人工。「待审批」不是第 ⑤ 步的输出，而是坐席审阅含审批项的草稿后主动「提交审批」的结果。

| 步骤 | 输入 | 处理 | 输出 | 失败时 |
|---|---|---|---|---|
| ① 接收与关联 | 亚马逊买家消息（亚马逊邮件中转到店铺绑定邮箱）、Shopify 与直邮邮件，均经 Gmail API 收取 | 去重（R-TK-07）；识别店铺（收件邮箱；亚马逊另按发件域 amazon.com / .ca / .com.mx 识别站点）；识别来源（客户、平台通知、已登记生产厂、其他供应商）；在该店铺内关联订单（平台订单镜像，D-21）与客户；按 R-TK-01 归并到工单 | 工单与消息；SLA 开始计时 | 店铺识别不出 → 进「未归属店铺」队列（E-13）；订单关联不上 → 继续处理，草稿里一次问全订单信息 |
| ② 风险拦截 | 消息正文、客户历史 | 对照风险信号清单（R-RS） | 命中 → 转人工并写明信号与原文；未命中 → 进入 ③ | 模型不可用 → 按关键词规则拦截，其余跳过 ③ 与 ④ 的模型检查（规则检查照常，人工回复时「不越政策」由坐席确认），工单标「AI 未处理」进收件箱（E-03） |
| ③ 理解与处理 | 消息、订单、知识库 | 识别主意图、次意图、情绪、语言；执行该意图的处理规则（R-IN）：查数据、提出动作、生成 3 版草稿 | 草稿、依据、建议动作 | 同上 |
| ④ 回复检查 | 草稿 | 5 项检查（R-CK） | 通过项 / 未通过项 | 未通过项在草稿上标出，发送按钮不可用，直到修改后重新检查通过 |
| ⑤ 发送方式 | 检查结果、意图配置 | 按 R-SD 判定 | 自动发送 / 待审草稿（含审批项时在草稿上标出）/ 转人工 | — |

### 5.2 发送方式判定（R-SD）

按顺序判断，命中即停止：

| 顺序 | 条件 | 结果 | 工单状态 |
|---|---|---|---|
| 1 | 第 ② 步命中风险信号，或意图规则为「转人工」，或无法识别意图 | 转人工 | 转人工 |
| 2 | 第 ④ 步有未通过项，且置信度低于 50% | 转人工（原因：检查不通过且置信度极低） | 转人工 |
| 3 | 推荐版草稿承诺或包含高风险动作，或会产生 FSH 现金支出 | 待审草稿，草稿上标出审批项；坐席审阅后「提交审批」 | 待审草稿（提交审批后转待审批） |
| 4 | 意图在自动发送白名单、置信度 ≥ 该意图阈值、依据齐全、检查全部通过 | 自动发送 | 等客户 |
| 5 | 其他 | 待审草稿 | 待审草稿 |

起步白名单：订单查询、发票与收据。放开与熔断规则见 R-SD-02、R-SD-03。

### 5.3 审批单流程（动作审批与报备合一）

```
坐席或系统发起 → 待审批 ──批准──→ 执行中 ──全部成功──→ 已执行 → 发出绑定回复
                  │                  └─任一失败─→ 执行失败 →（重试 / 转人工操作清单）
                  ├──驳回（原因必填）──→ 已驳回 → 通知发起人，绑定回复不发出
                  └──发起人撤回──→ 已撤回 → 关联工单与售后单按驳回处理（R-AP-07）
```

一张审批单可以同时包含：动作（0 到多项）、报备（0 到多项）、绑定回复（0 或 1 封）。审批人、时限、执行方式见 R-AP。

### 5.4 售后流程

**两条创建路径**

| 路径 | 场景 | 谁创建 | 责任如何判定 | 下一步 |
|---|---|---|---|---|
| A 产品故障 | 排查两轮仍未解决，或客户照片、视频可判定故障；坐席、客服主管可在工单上「转售后确认」（I21）；客服主管、售后负责人也可在 P07 选择来源工单手工新建 | 系统自动创建（第三阶段起）或人工发起「待确认」售后单；手工新建同样进入待确认（D-25） | AI 建议，售后负责人在 P08 确认 | 确认后按处理方式推进 |
| B 工单直接处理 | 未收到与异常、到货问题需要补发；免退货退款或部分补偿 | 坐席在收件箱「提交审批」时同时创建（只在审批单含报备或寄件动作时，D-27） | 按 R-AS-02 规则判定，审批人批准即确认 | 审批通过后执行 |

路径 A 的售后单没有发起人。售后负责人在 P08 认为证据不足、还需排查时点「退回继续排查」（原因必填）：售后单转已取消（原因「退回继续排查」，没有产生费用），来源工单回到分诊中，系统按退回原因与排查树生成下一步排查草稿。

**三种处理方式**

| 处理方式 | 步骤 | 人工点 |

| 调整安装方式 | 发安装或使用指导（待审草稿）→ 等客户 7 天 → 解决则完成；未解决改为「寄配件」 | 坐席审草稿 |

补充说明：

1. 「回复发出」是事件，不是状态。坐席在转人工工单上先发的进展回复（不含审批项）不改变状态，只结束该来信的 SLA 计时。
2. 系统发起的审批单（例如生产厂报价后自动发起的快递费用报备）挂在售后单上，不改变工单状态。
3. 工单关闭时仍有未回复的来信，该来信 SLA 计为未达标（R-SL-07）。
4. 重复联系只在客户来信时判断：看这封来信之前我方最近一封回复是不是结论性回复（R-TK-03）。
5. 目标写「等客户 或 等内部」时按发送时的后续事项取：有进行中的关联售后单（且不在「回复客户」环节）→ 等内部；坐席发送时选「等外部」并写明在等谁（承运商查件、平台申诉、易仓）→ 等外部；否则等客户。等外部没有自动关闭，由客户来信、标记解决或手动转人工离开（D-27）。

**第一阶段工单生命周期（D-22、D-23、D-24）**：第一阶段没有 AI 分诊与坐席回复，状态只有待回复、等客户、已解决、已关闭，迁移如下：

| 当前状态 | 事件 | 目标状态 | 触发方 |
|---|---|---|---|
| （无） | 新来信，无可追加或重开的工单 | 待回复 | 系统 |
| 已关闭（30 天内） | 同一订单来信 | 待回复（重开） | 系统 |
| 待回复 | 识别到我方回复，且该回复之后没有未回复来信 | 等客户 | 系统 |
| 待回复 | 全部未回复来信都被「标记无需回复」 | 已解决 | 坐席 / 客服主管 |
| 已解决 | 5 秒内撤销「标记无需回复」 | 待回复 | 坐席 / 客服主管 |
| 待回复 | 14 天无新来信 | 已关闭（原因「未识别到回复」；其中的应回复来信 SLA 计未达标） | 系统 |
| 等客户、已解决 | 新来信 | 待回复 | 系统 |
| 等客户 | 7 天无来信 | 已关闭（原因「客户未回复」） | 系统 |
| 已解决 | 7 天无来信 | 已关闭（原因「已解决后无来信」） | 系统 |

7 天、14 天都从工单内最近一封来信（不论来源）的到达时间起算；期间有新来信则重新起算。状态迁移看「未回复来信」，不论来源：生产厂、其他供应商的来信同样让工单回到待回复（需要有人查看），但它们不是应回复来信，不计 SLA；工单量只计由客户来信触发的新建与重开（D-24，术语见 1.4）。每次迁移记录时间、事件与触发方，P05 状态流转逐步显示。

「标记无需回复」只对未关闭工单中的未回复来信可用，按单封来信操作，5 秒内可撤销；被标记的来信卡显示「无需回复 · 操作人 · 时刻」，全程记录生成一条事件行，该来信不计入 SLA（I18）。「指定店铺」在 5 秒撤销窗口结束后才提交归并：窗口内行已移出队列、浮层可撤销，撤销后来信回到队列，不产生工单（I17）。

第二阶段上线时，全部「待回复」映射为「转人工」（原因「人工处理」；更早的已按 14 天规则关闭）；其余状态不变。

**第二阶段**（D-25）：没有 AI 分诊与草稿，「分诊中」「待审草稿」「待审批」不出现。新来信（含重开）直接进入「转人工」，原因「人工处理」；坐席回复后按上方完整迁移表转等客户或等内部；提交审批后工单保持转人工（D-11），审批通过且执行成功、绑定回复发出后转等客户或等内部。重复联系按坐席选择的回复类型计数（R-TK-03），次数为 1 升优先级；风险信号拦截随第三阶段。售后负责人在 P08「退回继续排查」时，来源工单回到转人工（原因「人工处理」），不生成排查草稿。坐席可对单封来信「标记无需回复」（同第一阶段，例如客户只回一句致谢），该来信不计 SLA；也可「标记解决」。识别到系统外发出的回复（「已发送」中不是本系统发出、带回复邮件头的我方邮件）同样结束对应来信的 SLA 计时，工单按「坐席发送回复」迁移，消息标「系统外回复」。负责人：新工单为未分配，坐席在收件箱认领（标题区负责人为空时显示「认领」）或回复即成为负责人，客服主管可改派。优先级：默认普通；重复联系 1 次升一级，2 次升为紧急并提醒客服主管；客服主管可手动调整。关联售后单需要回复客户时，工单转「转人工」（原因「售后待回复」）并进入需处理，工单负责人收到站内通知（6.5「回复客户环节」，D-27）。界面见 I19–I21。

### 6.3 审批单

| 状态 | 进入条件 | 退出 |
|---|---|---|
| 待审批 | 发起 | 批准 → 执行中；驳回 → 已驳回；撤回 → 已撤回 |
| 已超时（标记） | 待审批超过 4 小时 | 仍可批准或驳回；标记保留用于统计 |
| 执行中 | 批准 | 全部动作成功 → 已执行；任一失败且自动重试 3 次后仍失败 → 执行失败 |
| 已执行 | 全部动作成功（人工操作清单回填完成视为成功） | 终态；随后发出绑定回复 |
| 执行失败 | 自动重试用尽 | 发起人「重试」→ 执行中；「转人工操作清单」→ 生成人工操作清单；期间工单保持原状态（待审批，或转人工）并标「执行失败」 |
| 已驳回 | 审批人驳回，原因必填 | 终态；发起人可修改后重新发起新审批单 |
| 已撤回 | 发起人在批准前撤回（系统发起的由关联售后单负责人撤回） | 终态；关联工单与售后单按驳回处理（R-AP-07） |

审批单内的每个报备项、动作项各有状态：待审批 / 已批准 / 已驳回 / 已作废。已作废只出现在易仓库存用尽改走无货分支时（R-AS-04），原报备项作废，按生产厂报价另起报备。

绑定回复发送前校验不通过（提交审批后客户又来信或出现新风险信号）时，审批单进入子状态「暂停待确认」：它是「已执行」之后、绑定回复发出之前的子状态（主状态仍为已执行，外部动作不撤回）。发起人选择「照常发送」→ 回复发出，工单按原规则转等客户或等内部；选择「放弃并改写」→ 绑定回复作废，工单回到待审草稿（转人工工单保持转人工），改写后的回复不再走审批（动作已执行、承诺已批准），发送前照常做回复检查，原来信与新来信的 SLA 都在改写后的回复发出时结束（D-24）。待审批期间客户又来信时，审批卡显示非阻断提示「提交后客户又来信 N 封」（D-23，A11）。

|---|---|---|---|
| 待确认 | 等售后负责人确认责任与处理方式 | 路径 A 自动创建（第三阶段起）、坐席或客服主管在工单上转售后确认（D-25）、客服主管或售后负责人手工新建；确认时提交的审批单、路径 B 的审批单被驳回或撤回后退回（路径 B 的单锁定给原发起人，见 R-AP-07） | 确认 → 进行中；取消或退回继续排查 → 已取消 |
| 进行中 | 按处理方式推进，字段「当前环节」「等待方」说明卡在哪 | 确认；路径 B 创建；系统发起的报备被驳回或撤回时保持进行中（当前环节「报备审批 · 待重新提交」） | 客户侧完成 → 已完成（由处理人或登记人设置，不要求登记齐全；缺字段的单照样计入完整率分母，只是不计入分子，D-23）；终止流程 → 已取消 |
| 已完成 | 客户侧处理完：单号已回复客户，或款项已执行并回复，或指导后客户确认解决 / 7 天无回复。包裹此时可能仍在运输，物流跟踪在原工单继续 | — | 终态；比例协商与结算可以在完成后继续 |
| 已取消 | 终止流程，原因必填；已产生的费用照常登记 | — | 终态 |

**负责人与发起人**：售后单负责人 = 有该店铺数据范围的售后负责人（示例四个店铺均为王磊），负责推进和处理例外；路径 B 中提交审批的坐席记为「发起人」，可查看售后单、接收进展通知、在被驳回后重新提交。路径 A（含手工新建）没有发起人。

**回复客户环节**（D-27）：寄配件的单号回传后当前环节转「单号回复客户」，确认为调整安装方式后当前环节为「发送指导」，两者的等待方都是来源工单的负责人（未分配时为客服团队），来源工单按 6.1 转回待处理（第三阶段生成单号回复或指导草稿，第二阶段转人工 · 售后待回复）。来源工单上发出正文含该快递单号的回复即完成「单号回复客户」，售后单转已完成；发出任一我方回复即完成「发送指导」，当前环节转「等客户反馈」，客户确认解决或 7 天无来信转已完成，客户说未解决时售后负责人改为寄配件（5.4）。

**生产厂**：只在有生产厂参与（询价、寄件或比例协商）时填写，按配件 SKU 归属（R-FT-07）；易仓发货且无需协商的售后单不填；第一阶段手工登记时，任一组工厂承担比例大于 0 即须填写（寄配件按配件 SKU 预填，R-AS-08）。

**第一阶段手工登记的单在第二阶段**（D-25）：进行中的手工登记单在 P07 中当前环节写「手工登记 · 待补登」、等待方为负责人，仍用台账的编辑登记、设为已完成、取消处理（P13 行尾「更多」，S14、S15），不进入确认与执行流程；已完成、已取消的原样保留。承担比例以登记值为准：三组工厂比例都为 0 的协商与结算都为「不适用」；其余协商记为「已确认」、结算记为「待结算」，进入第二阶段上线当月的月末批次，生产厂对比例有异议时在批次确认时提出（E-30）。边界（D-27）：① 上线时比例确认时间记为上线时刻，只进入上线当月的月末批次，当月提前生成的批次不收这些单；② 此后编辑登记中的承担比例只读，需要调整时在批次生成前用 P12「重开协商」，批次生成后在下一批次冲销；③ 工厂比例大于 0 但生产厂为空的单，结算记为「未定」（显示「待补生产厂」），售后负责人补登生产厂后转待结算；④ 已取消的单按确认保留的费用同样处理；创建路径为「历史导入」的单结算记为「不适用」，不进入批次（历史费用已在系统外结清）。界面见 S16。

**第一阶段台账状态**（D-22、D-24）：手工登记的售后单只有 进行中 / 已完成 / 已取消。进行中 → 已完成：登记人或负责人设置，不要求字段齐全，记完成时间，5 秒内可撤销；进行中 → 已取消：客服主管或售后负责人操作，原因必填、二次确认，并确认保留的已产生费用；已完成、已取消为终态。进行中的单由登记人或负责人在「编辑登记」抽屉修改全部字段；已完成的单只由售后负责人补登缺失的适用字段（S13–S15）。负责人登记时必填，只能选有该店铺数据范围的售后负责人：登记人是售后负责人时默认本人，该店铺只有一位售后负责人时默认此人，否则必选（D-24）。第二阶段上线时三种状态原样保留，创建路径「手工登记」「历史导入」不变。

**当前环节**显示格式为「环节」或「环节 · 子状态」。环节取值：确认责任与处理方式 · 生产厂报价 · 报备审批 · 易仓发货 · 生产厂寄件 · 单号回复客户 · 发送指导 · 执行付款 · 等客户反馈 · 比例协商 · 待内部结算 · 已完成 · 手工登记（第一阶段遗留，D-25）。子状态取值：报备审批 → 快递费用 / 额外赔偿 / 待重新提交；易仓发货 → 等确认取消原补单（R-AS-04）；手工登记 → 待补登；比例协商 → 待工厂答复 / 工厂还价 / 待升级；已完成 → 已结算 / 向〈承运商或易仓〉索赔中。「在等谁」为当前环节的等待方；「已等」为进入当前环节以来的时长（例：S-20260903-0012 于 09-09 09:00 升级，10:20 时显示「2 天」）。

### 6.6 比例协商

| 状态 | 含义 |
|---|---|
| 不适用 | 责任为客户使用问题或物流问题，或三组费用的工厂承担比例都是 0 |
| 未发起 | 需要协商，但报备尚未通过 |
| 待工厂答复 | 已在工厂工作台发起提案，3 个工作日内答复；到期未答复自动催办 1 次，再过 2 个工作日转待升级 |
| 工厂还价 | 生产厂按三组费用提出新比例与理由，等 FSH 售后负责人处理 |
| 待升级 | 生产厂拒绝、答复超时、提案达 3 轮，或售后负责人在工厂还价后主动升级；由双方负责人线下商定，进入待升级后 3 个工作日内录入结果，到期提醒售后负责人与客服主管（R-CL-02） |
| 已确认 | 生产厂接受，或售后负责人录入商定比例（需填依据与商定人）；比例锁定 |

| 从 | 事件 | 到 | 触发者 |
|---|---|---|---|
| 未发起 | 报备通过（无报备时为确认完成） | 待工厂答复 | 系统 |
| 待工厂答复 | 生产厂接受 / 还价 / 拒绝 | 已确认 / 工厂还价 / 待升级 | 生产厂 |
| 待工厂答复 | 3 个工作日未答复，催办 1 次后再过 2 个工作日 | 待升级 | 系统 |
| 工厂还价 | 接受还价 / 再次提案（第 2、3 轮）/ 升级 | 已确认 / 待工厂答复 / 待升级 | 售后负责人 |
| 待升级 | 录入双方负责人商定的比例 | 已确认 | 售后负责人 |
| 已确认 | 重开协商（仅限进入结算批次前，原因必填；轮次从 1 重新计算） | 待工厂答复 | 售后负责人 |

### 6.7 内部结算

| 状态 | 含义 |
|---|---|
| 不适用 | 三组费用的工厂承担比例都是 0 |
| 未定 | 比例尚未确认，按建议比例估算，不进入批次 |
| 待结算 | 比例已确认，等待进入批次 |
| 已结算 | 批次经 FSH 售后负责人与生产厂对接人双方确认 |

每个生产厂每月至少一个批次：月末自动生成；也可提前生成，提前批次只收当时比例已确认的售后单，月末批次收其余；已入批的售后单不能重复纳入（D-22）。售后单按比例确认的时间归月：当月确认的进入当月的批次（D-24）。编号「年-月-生产厂-序号」（例 2026-09-FQD-A），分别推送各厂对接人确认。批次状态：待生成 → 待确认 → 已结算。批次生成后，其中售后单的比例不能再改；需要调整时在下一批次做冲销（Q-13 已确认）；具体付款方式（转账或抵扣货款）由财务定，系统只出批次与金额。

### 6.8 工厂任务

| 状态 | 含义 |
|---|---|
| 待处理 | 已派发给生产厂，计时中 |
| 已提交 | 生产厂已提交（报价、单号、比例答复、结算确认），等 FSH 侧处理 |
| 已退回 | FSH 退回修改（原因必填），回到生产厂待处理 |
| 已完成 | 该任务的后续流程已结束 |
| 已取消 | 售后单终止或改走易仓分支 |

任务类型与时限：询价报价 2 个工作日；寄件回填单号 3 个工作日；比例答复 3 个工作日；结算确认 5 个工作日。截止时刻按 R-CL-02 计算，界面同时显示剩余与截止时刻。

### 6.9 渠道连接

已连接 · 同步延迟（最近一次同步超过该数据源的阈值：Gmail、订单、积加 10 分钟，钉钉 2 小时，17TRACK 5 小时（每 4 小时一轮），汇率 1 天，D-23、D-24）· 连接异常（连续 3 次失败）· 未连接。连接异常时全站顶部显示红色横幅（G4），来信暂存，恢复后按到达顺序处理。

连接状态按店铺计算：渠道卡显示该渠道下最差的状态，并列出异常的邮箱或店铺；店铺表「状态」列显示该店铺各连接的状态。钉钉例外：同步延迟或连接异常只在 P18 钉钉卡显示，只给管理员发站内提醒，不出全站横幅；同步失败期间成员与部门保持上次结果，登录与权限不受影响（E-32、D-24）。全站横幅不可关闭，连接恢复后自动消失。

### 7.2 SLA 与工作日历（R-SL、R-CL）

| 编号 | 规则 |
|---|---|
| R-SL-01 | SLA 以「每一封客户来信」为对象：从来信到达邮箱起（计时口径见 R-SL-08），到我方对该来信的第一封回复成功发出止。 |

| R-SL-07 | 工单关闭或合并时仍有未回复的来信，该来信 SLA 计为未达标。 |

| R-CL-02 | FSH 与两家生产厂使用同一工作时间，在设置菜单「SLA」页由客服主管维护。计算：起算时刻为派发时刻，落在非工作时间时取下一个工作时间开始（09:00）；以工作日计的时限，截止时刻 = 起算时刻按工作日顺延 N 天的同一时刻；以工作小时计的时限，在工作时间内累加（例：周五 16:00 生成的人工操作清单，4 个工作小时 → 下周一 11:00）。显示：同时写剩余与截止时刻；剩余 ≥ 9 个工作小时写「剩 N 个工作日」（剩余工作小时 ÷ 9，向上取整），不足 9 个工作小时写「剩 N 个工作小时」（向上取整）。例：周五 09-11 08:50 派发询价（2 个工作日）→ 从 09:00 起算 → 截止 09-15 周二 09:00；10:20 时剩余 16h40m 工作时间，显示「剩 2 个工作日 · 09-15 周二 09:00 截止」。 |

| 到货问题 | 售后 | 照片、实际收到的物品 | 订单明细、易仓出库记录 | 补发（报备快递费用）、退款 | 待审草稿（含审批项） |
| 产品故障与使用问题 | 售后 | 症状、购买日期、照片或视频 | 故障排查树、保修期 | 排查步骤；两轮未解决创建售后单（路径 A） | 待审草稿 |
| 退货与退款 | 售后 | 订单号、原因 | 站点退货政策与窗口 | 退货指引（低风险）；退货退款（高风险）；免退货退款（报备额外赔偿） | 待审草稿（退款时含审批项） |
| 保修与配件购买 | 售后 | 配件号或症状、购买日期 | 配件表、保修条款、报价 | 报价（低风险）；付款后创建售后单 | 待审草稿 |
| 发票与收据 | 售后 | 订单号 | 平台发票 | 邮件渠道生成并附发票；亚马逊渠道不附件，以纯文字指引买家在订单页获取发票（低风险，D-22） | 自动发送 |
| 评价与反馈 | 售后 | 无 | 无 | 无；亚马逊限制此类沟通 | 转人工 |

「默认发送方式」只有自动发送、待审草稿、转人工三种；含审批项的草稿由坐席审阅后提交审批（D-11）。

非业务消息：致谢与确认 → 标记无需回复，工单转已解决（7 天后自动关闭）；来自已登记生产厂的邮件 → 转人工并提醒改用工厂工作台，不解析其中的报价或单号（R-FT-06）；其他供应商邮件 → 转人工；平台通知与垃圾 → 归档，不建工单。多意图时主意图决定规则，次意图在同一封回复中顺带回答。

### 7.4 风险信号（R-RS）

| 信号 | 判定 | 优先级 |
|---|---|---|
| 安全事故 | 起火、冒烟、过热、烫伤、电池鼓包 | 紧急，人工处理并留档 |
| 平台风险 | A-to-Z、拒付、差评或 feedback 威胁、投诉到平台、律师或法律 | 紧急 |
| 重复联系 | 重复联系次数达到 2（R-TK-03；次数为 1 时只升优先级，不拦截） | 高 |
| 高价值 | 订单金额或客户累计消费超过阈值（默认 $300，Q-10 默认值已设） | 高 |
| 要求真人 | 客户明确要求与人沟通 | 高 |
| 无法处理的内容 | 不支持的语言、乱码、只有附件 | 普通 |
| 疑似提示注入 | 来信中含有试图改变系统行为的指令（例如要求忽略规则、直接退款、透露内部信息），附原文片段（D-21） | 高 |

情绪只有负面、中性、正面三档，用于排序、报表与语气，不决定是否转人工。

风险信号由关键词规则（英语、西班牙语）与模型并行判定、结果取并集，每个命中信号附原文片段；安全事故与平台风险任一方命中即转人工；模型不可用时只用关键词（E-03）。另从来信中识别紧急度（客户要求的截止日期、高 / 中 / 低），用于排序与方案选择（D-21）。

### 7.5 回复检查（R-CK）

| 检查项 | 通过标准 |
|---|---|
| 事实有来源 | 每个事实能追溯到订单数据或知识条目 |
| 不越政策 | 不承诺政策以外的补偿、时限、退款 |
| 渠道内容能力 | 亚马逊：无链接、无图片、无营销、无站外联系方式；邮件：图片只来自素材库，链接只在白名单 |
| 语言一致 | 回复语言与客户来信语言一致；西班牙语用 usted 敬语 |
| 不泄露内部信息 | 不出现内部备注、成本、生产厂、其他店铺订单 |

第二阶段人工回复只做规则项：亚马逊回复不含链接、图片与站外联系方式（按 R-CC 判定，未通过时发送按钮不可用并标出）；事实有来源、不越政策、语言一致、不泄露内部信息随第三阶段（D-27）。

### 7.6 发送方式、放开与熔断（R-SD）

| 编号 | 规则 |
|---|---|
| R-SD-01 | 判定顺序见 5.2。 |
| R-SD-02 | 放开自动发送：某意图连续 30 天采纳率高于 90% 且样本不少于 50 封，客服主管可在 P19 切换为自动发送；条件不满足时开关禁用并显示原因。 |
| R-SD-03 | 熔断：任一自动发送意图 24 小时内被拒绝或修改超过 30%，自动降回待审草稿并通知客服主管。自动发送的回复每天按意图抽检，抽检量 = min(当日自动发送数, max(10%, 5 封))，由客服主管在工单详情标注「合格 / 需修改」。熔断比例 = （人工审阅中被拒绝或修改的 + 抽检中「需修改」的）÷（人工审阅数 + 抽检数）；抽检样本不足 5 封时按滚动 7 天累计判断，仍不足不视为合格并提醒补抽（D-22、D-23）。 |
| R-SD-04 | 草稿采纳率 = 未修改直接发送的草稿数 ÷ 坐席审阅过的草稿数。 |
| R-SD-05 | 置信度为可复算的综合分：依据是否齐全（需要的信息都已取得）、回复检查是否全部通过、该意图近 30 天采纳率，并参考意图判断是否与关键词规则冲突；不使用模型自报的数值。本节与 R-KB-04 的阈值都按此口径（D-21）。 |
| R-SD-06 | 放开或恢复某意图的自动发送，除 R-SD-02 的条件外，该意图的回归样例须连续 5 次全部通过；修改提示、模型或意图流程后须重新通过（D-21）。 |

### 7.7 审批单（R-AP）

| 编号 | 规则 |
|---|---|
| R-AP-01 | 需要审批：高风险动作（退款、改地址、取消、补发、创建售后出库单、通知生产厂寄出）；报备（R-FL）。同一次处理的动作、报备、绑定回复合成一张审批单。 |
| R-AP-02 | 审批人：含报备 → 客服主管；只含动作 → 客服主管或售后负责人任一人。发起人不能审批自己发起的审批单；发起人恰好是唯一有权审批的人时（例如唯一的客服主管自己发起报备），审批单转给备用审批人。备用审批人由管理员在 P20 指定，默认售后负责人王磊（Q-19 已确认）。审批单剩 1 小时仍未处理时，备用审批人也可以审批（含报备的单也可，R-AP-03）。 |
| R-AP-03 | 时限 4 小时。剩 1 小时提醒审批人，同时提醒备用审批人（默认王磊），此后备用审批人可审批；超时标记「已超时」，同时通知发起人和其他有审批权的人，仍可审批。处理锁：审批单被有权审批的人打开即加锁，其他有权审批的人只读并看到「谁正在处理 · 何时起」；关闭审批单或 10 分钟无操作释放。批准、驳回以持锁人为准，防止重复审批（A10）。 |
| R-AP-04 | 批准后动作按顺序执行：由接口自动执行（退款、改地址、取消经亚马逊 SP-API 或 Shopify Admin API，Q-23 已确认；亚马逊退款、取消经 Feeds 异步执行，提交后审批项保持「执行中」直到处理报告返回（最长约 8 小时），绑定回复在处理报告成功后才发出（D-21）；创建易仓售后出库单经积加，Q-25 已确认）；需要生产厂的在工厂工作台生成任务。人工操作清单只作兜底：接口重试用尽后发起人转交（R-AP-05），或某项动作暂无接口。动作与适配器的对应见 P22 动作映射。 |
| R-AP-05 | 自动执行初次失败后最多重试 3 次（共最多 4 次尝试），相邻两次间隔依次为 1、5、15 分钟（例：10:52 失败 → 10:53、10:58、11:13 重试）；仍失败则状态「执行失败」，通知发起人，可重试或转为人工操作清单。亚马逊 Feeds 以处理报告为准：报告失败按本条重试；结果不明时先查询，不重复提交（D-21）。 |
| R-AP-06 | 绑定回复在全部动作成功后自动发出；任一动作失败则回复不发出。积加补发以积加回传「已推送易仓且未缺货」为成功，超过 4 个工作小时仍未确认则生成人工操作清单；亚马逊 Feeds 以处理报告成功为准。发送前校验：提交审批后客户又来信或出现新风险信号时暂停发送，转发起人确认（审批单子状态「暂停待确认」，见 6.3）；已执行的外部动作不撤回，只核对事实（D-22）。 |
| R-AP-07 | 驳回必须填原因；发起人在批准前撤回，与驳回同样处理。按审批单来源分三种：① 售后负责人在 P08 确认时提交的：售后单退回「待确认」，售后负责人在 P08 修改后重新提交。② 坐席在收件箱提交的（路径 B）：售后单退回「待确认」并锁定给原发起人，坐席在工单上修改后重新提交，复用同一售后单号；P08 对这类单只读，提示「等坐席重新提交」。③ 系统发起的（生产厂报价后的快递费用报备、补充报备）：售后单保持进行中，当前环节「报备审批 · 待重新提交」，售后负责人在售后单详情修改金额后重新提交，或退回生产厂重新报价。 |
| R-AP-08 | 人工操作清单指派给发起人，4 个工作小时内回填；回填金额须与审批金额一致，不一致需填说明并由原审批人确认。 |

### 7.9 售后责任、处理方式与承担比例（R-AS）

| 编号 | 规则 |

白名单起步：各店铺域名（forcome.com、forcome.mx）、说明书与视频托管域名、承运商查询页。同一排查内容在素材库里同时保存图文版与纯文字版。素材库与链接白名单随第三阶段（P16、P19 K16）；第二阶段回复框没有插入图片与插入链接按钮，邮件回复可直接写链接、不校验白名单（D-27）。

### 7.11 多店铺（R-ST）

| 编号 | 规则 |
|---|---|
| R-ST-01 | 店铺是工单的维度加一层配置覆盖，流程只有一套。 |
| R-ST-02 | 进线识别：亚马逊按买家消息的收件邮箱识别店铺（每个店铺在卖家后台绑定一个邮箱）、按发件域（amazon.com / .ca / .com.mx）识别站点；Shopify 与直邮按客服邮箱。识别不出进「未归属店铺」队列，由客服主管指定；系统按收件地址（前缀、域名）与买家历史订单 ✦ 推荐店铺，写明依据与生成时间，主管确认后生效（I14；第一阶段没有推荐，I17）。管理员登记新店铺或为现有店铺增加进线邮箱（含别名）后，队列中收件地址与之匹配的来信自动归位并通知客服主管（D-24）。未归属来信对客服主管可见、不受店铺数据范围限制（来信尚无店铺），指定时只能选其授权店铺。 |
| R-ST-03 | 订单只在该店铺内匹配。回复从来信的同一店铺身份发出，使用该店铺签名；动作取该店铺凭据；禁止跨店铺发送。 |
| R-ST-04 | 配置按「全局 → 平台 → 店铺」三层取值。店铺可覆盖：签名、政策口径、模板、素材与链接白名单、SLA 内部目标。意图、风险信号、动作分级只能全局配置。签名、模板、SLA 内部目标随第二阶段上线，政策口径、素材与链接白名单随第三阶段（依赖知识库与 P19，D-27）；第一阶段不发信、不用模型，签名与覆盖项不显示（D-24）。 |
| R-ST-05 | 采纳率按意图全局统计；个别店铺可单独降回待审草稿。 |
| R-ST-06 | 成员按店铺授权数据范围；顶部店铺选择只能在授权范围内切换，页面里的店铺筛选初始值跟随它、可再收窄（顶部店铺选择随第二阶段收件箱上线，第一阶段只有页面店铺筛选，D-24）。 |
| R-ST-07 | 客户档案可跨店铺合并（人工确认）；对客户的回复不提及其在其他店铺的订单。 |

### 7.12 语言与翻译（R-LG）

| 编号 | 规则 |
|---|---|
| R-LG-01 | 自动识别来信语言，非中文来信生成中文译文，坐席可在原文与译文间切换，或并排查看。 |
| R-LG-02 | 回复语言默认等于来信语言。首批支持英语、西班牙语（客户确认 Q-16：站点为美国、加拿大、墨西哥）；不支持的语言按风险信号「无法处理的内容」转人工。 |
| R-LG-03 | 坐席可用中文写回复（第二阶段起）或修改草稿（第三阶段）；发送前生成目标语言译文并显示回译，坐席确认后发出（D-25、D-27）。 |
| R-LG-04 | 对客户的文本里出现时间时，按客户所在时区书写并注明时区（例：「by 2:00 PM ET」），不写北京时间；进展回复不写具体时刻（R-SL-05）。 |

### 7.13 草稿版本、标签与知识库

| 编号 | 规则 |
|---|---|
| R-DF-01 | 每封需回复的来信生成 3 版草稿，按解决方案区分；只有一种合理方案时生成 1 版并说明原因。「换一版」每次新增 1 版，同一来信最多 5 版。 |
| R-DF-02 | 记录最终采纳的版本与是否修改；拒绝必选原因，选「知识错误」时自动生成知识缺口。 |
| R-TG-01 | 标签库由客服主管维护，坐席只能选用；一张工单最多 5 个标签；报表可按标签筛选。 |
| R-KB-01 | 知识四层：产品事实表、政策规则、故障排查树、模板与素材；另有沉淀问答。每条带适用店铺（默认全部）、语言、渠道、负责人、有效期。 |
| R-KB-02 | 有效期到期前 7 天提醒负责人；过期条目不参与检索。 |
| R-KB-03 | 坐席可把已解决工单标记为 FAQ 候选，知识库负责人审核后入库。 |
| R-KB-04 | 转人工、拒绝原因为知识错误、置信度低于 60% 的草稿，自动进入知识缺口清单，每周处理。系统把相近缺口聚类，并 ✦ 起草条目草稿，知识库负责人审核后才入库（D-20）。 |
| R-AI-01 | 所有 AI 生成内容（草稿、摘要、译文、分析、推荐与预填）统一用 ✦ 标识，并写「生成时间 · 依据」。智能化建议——AI 预选责任类型、推荐店铺、推荐负责人、预填商定依据、报价参考、积加单号预填、知识缺口聚类起草——都需人工确认后生效，确认人记入审计日志（D-20）。 |

### 7.14 工厂工作台（R-FT）

| 编号 | 规则 |
|---|---|
| R-FT-01 | 生产厂对接人登录工厂工作台，只看到本厂任务。 |
| R-FT-02 | 可见字段：询价——配件、数量、目的国与邮编、故障描述与照片；寄件——收件人姓名、完整地址、电话（寄件完成 30 天后隐藏）；比例协商——责任类型、判定依据、费用合计及产品成本、运费、额外赔偿、其他四项构成，以及按三组费用的比例（额外赔偿只显示金额，不显示订单号与售价）；结算确认——批次内售后单号、费用合计、比例、工厂承担金额。不显示客户邮箱、售价、店铺后台信息。 |
| R-FT-03 | 生产厂提交的报价、单号、实际运费、比例答复直接写入登记台账，不经邮件。 |
| R-FT-04 | 每个售后单有一个与生产厂共享的留言线程，可附图片；留言随售后单存档。 |
| R-FT-05 | 新任务、催办、FSH 留言推送到对接人的钉钉工作通知；点开即在钉钉内免登进入工厂工作台对应任务。 |
| R-FT-06 | 生产厂若仍发邮件到客服邮箱，系统转人工并提醒改用工厂工作台；报价、单号、比例答复只认工作台里的提交。 |
| R-FT-07 | 配件与整机全部由集团内两家生产厂生产（客户确认 Q-22）：FQD、FZJ。售后单按 SKU 归属派发询价、寄件与比例协商，各厂只看本厂任务。SKU 归属在 P24「工厂账号 · 负责的 SKU」维护，上线前由 FSH 与两厂整理导入（原型示例：FQD 负责整机、电池、软管、HEPA 滤芯、集尘杯；FZJ 负责充电线）。每个生产厂每月至少一个结算批次（可提前生成，见 6.7），分别确认。 |
| R-FT-08 | 生产厂成员来自钉钉通讯录中两家生产厂的部门；管理员在 P24 选择对接人并分配「生产厂对接人」角色，负责人不分配系统角色。 |
