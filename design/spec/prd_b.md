## 5 核心流程

### 5.1 每封来信的五步处理

```
来信 → ① 接收与关联 → ② 风险拦截 →（命中）转人工
                          ↓（未命中）
                     ③ 理解与处理 → ④ 回复检查 → ⑤ 发送方式 → 自动发送 / 待审草稿 / 转人工
                                                                  ↓（草稿含审批项）
                                              坐席审阅 → 提交审批 → 待审批
```

第 ⑤ 步只输出三种结果：自动发送、待审草稿、转人工。「待审批」不是第 ⑤ 步的输出，而是坐席审阅含审批项的草稿后主动「提交审批」的结果。

| 步骤 | 输入 | 处理 | 输出 | 失败时 |
|---|---|---|---|---|
| ① 接收与关联 | 亚马逊买家消息（亚马逊邮件中转到店铺绑定邮箱）、Shopify 与直邮邮件，均经 Gmail API 收取 | 去重（Message-ID）；识别店铺（收件邮箱；亚马逊另按发件域 amazon.com / .ca / .com.mx 识别站点）；识别来源（客户、平台通知、已登记生产厂、其他供应商）；在该店铺内关联订单（积加）与客户；按 R-TK-01 归并到工单 | 工单与消息；SLA 开始计时 | 店铺识别不出 → 进「未归属店铺」队列（E-13）；订单关联不上 → 继续处理，草稿里一次问全订单信息 |
| ② 风险拦截 | 消息正文、客户历史 | 对照风险信号清单（R-RS） | 命中 → 转人工并写明信号与原文；未命中 → 进入 ③ | 模型不可用 → 按关键词规则拦截，其余跳过 ③④，工单标「AI 未处理」进收件箱（E-03） |
| ③ 理解与处理 | 消息、订单、知识库 | 识别主意图、次意图、情绪、语言；执行该意图的处理规则（R-IN）：查数据、提出动作、生成 3 版草稿 | 草稿、依据、建议动作 | 同上 |
| ④ 回复检查 | 草稿 | 5 项检查（R-CK） | 通过项 / 未通过项 | 未通过项在草稿上标出，发送按钮不可用，直到修改后重新检查通过 |
| ⑤ 发送方式 | 检查结果、意图配置 | 按 R-SD 判定 | 自动发送 / 待审草稿（含审批项时在草稿上标出）/ 转人工 | — |

### 5.2 发送方式判定（R-SD）

按顺序判断，命中即停止：

| 顺序 | 条件 | 结果 | 工单状态 |
|---|---|---|---|
| 1 | 第 ② 步命中风险信号，或意图规则为「转人工」，或无法识别意图 | 转人工 | 转人工 |
| 2 | 第 ④ 步有未通过项，且置信度低于 50% | 转人工（原因：检查不通过且置信度极低） | 转人工 |
| 3 | 推荐版草稿承诺或包含高风险动作，或会产生 FSH 现金支出 | 待审草稿，草稿上标出审批项；坐席审阅后「提交审批」 | 待审草稿（提交审批后转待审批） |
| 4 | 意图在自动发送白名单、置信度 ≥ 该意图阈值、依据齐全、检查全部通过 | 自动发送 | 等客户 |
| 5 | 其他 | 待审草稿 | 待审草稿 |

起步白名单：订单查询、发票与收据。放开与熔断规则见 R-SD-02、R-SD-03。

### 5.3 审批单流程（动作审批与报备合一）

```
坐席或系统发起 → 待审批 ──批准──→ 执行中 ──全部成功──→ 已执行 → 发出绑定回复
                  │                  └─任一失败─→ 执行失败 →（重试 / 转人工操作清单）
                  ├──驳回（原因必填）──→ 已驳回 → 通知发起人，绑定回复不发出
                  └──发起人撤回──→ 已撤回 → 关联工单与售后单按驳回处理（R-AP-07）
```

一张审批单可以同时包含：动作（0 到多项）、报备（0 到多项）、绑定回复（0 或 1 封）。审批人、时限、执行方式见 R-AP。

### 5.4 售后流程

**两条创建路径**

| 路径 | 场景 | 谁创建 | 责任如何判定 | 下一步 |
|---|---|---|---|---|
| A 产品故障 | 排查两轮仍未解决，或客户照片、视频可判定故障；售后负责人也可在 P07 选择来源工单手工新建 | 系统自动创建「待确认」售后单；手工新建同样进入待确认 | AI 建议，售后负责人在 P08 确认 | 确认后按处理方式推进 |
| B 工单直接处理 | 未收到与异常、到货问题需要补发；免退货退款或部分补偿 | 坐席在收件箱「提交审批」时同时创建 | 按 R-AS-02 规则判定，审批人批准即确认 | 审批通过后执行 |

路径 A 的售后单没有发起人。售后负责人在 P08 认为证据不足、还需排查时点「退回继续排查」（原因必填）：售后单转已取消（原因「退回继续排查」，没有产生费用），来源工单回到分诊中，系统按退回原因与排查树生成下一步排查草稿。

**三种处理方式**

| 处理方式 | 步骤 | 人工点 |
|---|---|---|
| 调整安装方式 | 发安装或使用指导（待审草稿）→ 等客户 7 天 → 解决则完成；未解决改为「寄配件」 | 坐席审草稿 |
| 寄配件 · 良仓有货（含换新、整机补发） | 按良仓运费试算估算运费 → 报备快递费用（附售后出库单参数）→ 批准即经积加创建良仓售后出库单 → 良仓发出，经积加回传单号与实际运费 → 单号回复客户 → 完成 | 报备审批 |
| 寄配件 · 良仓无货 | 工厂工作台向配件对应的生产厂（FQD / FZJ）派发询价 → 生产厂报价 → 报备快递费用 → 批准即生成寄件任务 → 生产厂回填单号与实际运费 → 单号回复客户 → 完成 | 报备审批 |
| 退款或部分补偿 | 金额提案 → 报备额外赔偿 → 批准后经接口执行付款（亚马逊 SP-API、Shopify Admin API；重试用尽才转人工操作清单）→ 付款成功后绑定回复自动发出 → 完成 | 报备审批 |

比例协商与寄件、付款并行，客户不等协商结果。

### 5.5 比例协商与内部结算

```
报备通过（或无报备的确认完成）→ 需要协商？ ──否──→ 比例按规则生效（不适用）
                                    │是
                                    ↓
                  工厂工作台发起提案 → 待工厂答复 ──接受──→ 已确认 → 进入结算
                                          ├─还价─→ 工厂还价 →（接受 / 再次提案 / 售后负责人主动升级）
                                          ├─拒绝─→ 待升级
                                          └─超时 3+2 个工作日─→ 待升级
                  待升级 → 双方负责人商定 → 售后负责人录入最终比例 → 已确认
已确认的售后单 → 按生产厂的月度批次（每月 5 日生成上月批次，可提前）→ 双方确认 → 已结算
```

| 转人工 | 坐席发送回复（无审批项，且没有挂着未结束的审批单） | 等客户 或 等内部 | 坐席 |
| 任一未关闭状态 | 客户来信 | 分诊中（重复联系按 R-TK-03 计数） | 系统 |
| 任一未关闭状态 | 转人工 | 转人工 | 坐席 |
| 等内部 | 关联售后单被「退回继续排查」 | 分诊中（生成下一步排查草稿） | 售后负责人 |
| 等客户、等内部、等外部 | 标记解决 / 识别为致谢 | 已解决 | 坐席 / 系统 |
| 已解决、等客户 | 7 天无来信 | 已关闭 | 系统 |
| 任一未关闭状态 | 合并到其他工单 | 已合并 | 坐席 |
| 已解决、已关闭（≤ 30 天） | 重新打开 | 分诊中 | 坐席 |

补充说明：

1. 「回复发出」是事件，不是状态。坐席在转人工工单上先发的进展回复（不含审批项）不改变状态，只结束该来信的 SLA 计时。
2. 系统发起的审批单（例如生产厂报价后自动发起的快递费用报备）挂在售后单上，不改变工单状态。
3. 工单关闭时仍有未回复的来信，该来信 SLA 计为未达标（R-SL-07）。
4. 重复联系只在客户来信时判断：看这封来信之前我方最近一封回复是不是结论性回复（R-TK-03）。

### 6.2 AI 草稿

| 状态 | 含义 |
|---|---|
| 生成中 | 第 ③ 步生成中，收件箱显示转圈（I3） |
| 待审 | 等坐席审阅；同一来信最多 5 版 |
| 已采纳 | 发送成功；记录「未修改」或「修改后」 |
| 已拒绝 | 坐席拒绝，原因必选：知识错误 / 政策不符 / 语气不当 / 信息不全 / 其他 |
| 已失效 | 草稿生成后客户又来信；系统自动为新来信重新生成 |

### 6.3 审批单

| 状态 | 进入条件 | 退出 |
|---|---|---|
| 待审批 | 发起 | 批准 → 执行中；驳回 → 已驳回；撤回 → 已撤回 |
| 已超时（标记） | 待审批超过 4 小时 | 仍可批准或驳回；标记保留用于统计 |
| 执行中 | 批准 | 全部动作成功 → 已执行；任一失败且自动重试 3 次后仍失败 → 执行失败 |
| 已执行 | 全部动作成功（人工操作清单回填完成视为成功） | 终态；随后发出绑定回复 |
| 执行失败 | 自动重试用尽 | 发起人「重试」→ 执行中；「转人工操作清单」→ 生成人工操作清单；期间工单保持原状态（待审批，或转人工）并标「执行失败」 |
| 已驳回 | 审批人驳回，原因必填 | 终态；发起人可修改后重新发起新审批单 |
| 已撤回 | 发起人在批准前撤回（系统发起的由关联售后单负责人撤回） | 终态；关联工单与售后单按驳回处理（R-AP-07） |

审批单内的每个报备项、动作项各有状态：待审批 / 已批准 / 已驳回 / 已作废。已作废只出现在良仓库存用尽改走无货分支时（R-AS-04），原报备项作废，按生产厂报价另起报备。

### 6.4 人工操作清单

| 状态 | 含义 |
|---|---|
| 待执行 | 接口重试用尽后由发起人转交生成；或该动作暂无接口时审批通过即生成。指派给发起人，4 个工作小时内完成 |
| 已回填 | 执行人回填外部单号、金额、截图；金额与审批金额一致即完成，对应动作记为成功 |
| （回填不一致） | 回填金额与审批金额不同 → 不能提交，除非填写差异说明并由原审批人确认 |

### 6.5 售后单

| 状态 | 含义 | 进入 | 退出 |
|---|---|---|---|
| 待确认 | 等售后负责人确认责任与处理方式 | 路径 A 自动创建或售后负责人手工新建；确认时提交的审批单、路径 B 的审批单被驳回或撤回后退回（路径 B 的单锁定给原发起人，见 R-AP-07） | 确认 → 进行中；取消或退回继续排查 → 已取消 |
| 进行中 | 按处理方式推进，字段「当前环节」「等待方」说明卡在哪 | 确认；路径 B 创建；系统发起的报备被驳回或撤回时保持进行中（当前环节「报备审批 · 待重新提交」） | 客户侧完成且登记齐全 → 已完成；终止流程 → 已取消 |
| 已完成 | 客户侧处理完：单号已回复客户，或款项已执行并回复，或指导后客户确认解决 / 7 天无回复。包裹此时可能仍在运输，物流跟踪在原工单继续 | — | 终态；比例协商与结算可以在完成后继续 |
| 已取消 | 终止流程，原因必填；已产生的费用照常登记 | — | 终态 |

**负责人与发起人**：售后单负责人 = 按店铺分配的售后负责人（示例四个店铺均为王磊），负责推进和处理例外；路径 B 中提交审批的坐席记为「发起人」，可查看售后单、接收进展通知、在被驳回后重新提交。路径 A（含手工新建）没有发起人。

**生产厂**：只在有生产厂参与（询价、寄件或比例协商）时填写，按配件 SKU 归属（R-FT-07）；良仓发货且无需协商的售后单不填。

**当前环节**显示格式为「环节」或「环节 · 子状态」。环节取值：确认责任与处理方式 · 生产厂报价 · 报备审批 · 良仓发货 · 生产厂寄件 · 单号回复客户 · 执行付款 · 等客户反馈 · 比例协商 · 待内部结算 · 已完成。子状态取值：报备审批 → 快递费用 / 额外赔偿 / 待重新提交；比例协商 → 待工厂答复 / 工厂还价 / 待升级；已完成 → 已结算 / 向〈承运商或良仓〉索赔中。「在等谁」为当前环节的等待方；「已等」为进入当前环节以来的时长（例：S-20260903-0012 于 09-09 09:00 升级，10:20 时显示「2 天」）。

### 6.6 比例协商

| 状态 | 含义 |
|---|---|
| 不适用 | 责任为客户使用问题或物流问题，或三组费用的工厂承担比例都是 0 |
| 未发起 | 需要协商，但报备尚未通过 |
| 待工厂答复 | 已在工厂工作台发起提案，3 个工作日内答复；到期未答复自动催办 1 次，再过 2 个工作日转待升级 |
| 工厂还价 | 生产厂按三组费用提出新比例与理由，等 FSH 售后负责人处理 |
| 待升级 | 生产厂拒绝、答复超时、提案达 3 轮，或售后负责人在工厂还价后主动升级；由双方负责人线下商定 |
| 已确认 | 生产厂接受，或售后负责人录入商定比例（需填依据与商定人）；比例锁定 |

| 从 | 事件 | 到 | 触发者 |
|---|---|---|---|
| 未发起 | 报备通过（无报备时为确认完成） | 待工厂答复 | 系统 |
| 待工厂答复 | 生产厂接受 / 还价 / 拒绝 | 已确认 / 工厂还价 / 待升级 | 生产厂 |
| 待工厂答复 | 3 个工作日未答复，催办 1 次后再过 2 个工作日 | 待升级 | 系统 |
| 工厂还价 | 接受还价 / 再次提案（第 2、3 轮）/ 升级 | 已确认 / 待工厂答复 / 待升级 | 售后负责人 |
| 待升级 | 录入双方负责人商定的比例 | 已确认 | 售后负责人 |
| 已确认 | 重开协商（仅限进入结算批次前，原因必填；轮次从 1 重新计算） | 待工厂答复 | 售后负责人 |

### 6.7 内部结算

| 状态 | 含义 |
|---|---|
| 不适用 | 三组费用的工厂承担比例都是 0 |
| 未定 | 比例尚未确认，按建议比例估算，不进入批次 |
| 待结算 | 比例已确认，等待进入批次 |
| 已结算 | 批次经 FSH 售后负责人与生产厂对接人双方确认 |

每个生产厂每月一个批次，编号「年-月-生产厂-序号」（例 2026-09-FQD-A），分别推送各厂对接人确认。批次状态：待生成 → 待确认 → 已结算。批次生成后，其中售后单的比例不能再改；需要调整时在下一批次做冲销（Q-13 已确认）；具体付款方式（转账或抵扣货款）由财务定，系统只出批次与金额。

### 6.8 工厂任务

| 状态 | 含义 |
|---|---|
| 待处理 | 已派发给生产厂，计时中 |
| 已提交 | 生产厂已提交（报价、单号、比例答复、结算确认），等 FSH 侧处理 |
| 已退回 | FSH 退回修改（原因必填），回到生产厂待处理 |
| 已完成 | 该任务的后续流程已结束 |
| 已取消 | 售后单终止或改走良仓分支 |

任务类型与时限：询价报价 2 个工作日；寄件回填单号 3 个工作日；比例答复 3 个工作日；结算确认 5 个工作日。截止时刻按 R-CL-02 计算，界面同时显示剩余与截止时刻。

### 6.9 渠道连接

已连接 · 同步延迟（最近一次同步超过 10 分钟）· 连接异常（连续 3 次失败）· 未连接。连接异常时全站顶部显示红色横幅（G4），来信暂存，恢复后按到达顺序处理。

| R-TK-01 | 来信带订单号：同一店铺同一订单有未关闭工单则追加；有 30 天内关闭的工单则重开；否则新建。 |

|---|---|

| R-CL-02 | FSH 与两家生产厂使用同一工作时间，在 P19「SLA」页由客服主管维护。计算：起算时刻为派发时刻，落在非工作时间时取下一个工作时间开始（09:00）；以工作日计的时限，截止时刻 = 起算时刻按工作日顺延 N 天的同一时刻；以工作小时计的时限，在工作时间内累加（例：周五 16:00 生成的人工操作清单，4 个工作小时 → 下周一 11:00）。显示：同时写剩余与截止时刻；剩余 ≥ 9 个工作小时写「剩 N 个工作日」（剩余工作小时 ÷ 9，向上取整），不足 9 个工作小时写「剩 N 个工作小时」（向上取整）。例：周五 09-11 08:50 派发询价（2 个工作日）→ 从 09:00 起算 → 截止 09-15 周二 09:00；10:20 时剩余 16h40m 工作时间，显示「剩 2 个工作日 · 09-15 周二 09:00 截止」。 |

| 要求真人 | 客户明确要求与人沟通 | 高 |

情绪只有负面、中性、正面三档，用于排序、报表与语气，不决定是否转人工。

### 7.5 回复检查（R-CK）

### 7.6 发送方式、放开与熔断（R-SD）

| R-SD-01 | 判定顺序见 5.2。 |

### 7.7 审批单（R-AP）

| 编号 | 规则 |
|---|---|
| R-AP-01 | 需要审批：高风险动作（退款、改地址、取消、补发、创建售后出库单、通知生产厂寄出）；报备（R-FL）。同一次处理的动作、报备、绑定回复合成一张审批单。 |
| R-AP-02 | 审批人：含报备 → 客服主管；只含动作 → 客服主管或售后负责人任一人。发起人不能审批自己发起的审批单；发起人恰好是唯一有权审批的人时（例如唯一的客服主管自己发起报备），审批单转给备用审批人。备用审批人由管理员在 P20 指定，默认售后负责人王磊（Q-19 已确认）。 |
| R-AP-03 | 时限 4 小时。剩 1 小时提醒审批人；超时标记「已超时」，同时通知发起人和其他有审批权的人，仍可审批。 |
| R-AP-04 | 批准后动作按顺序执行：由接口自动执行（退款、改地址、取消经亚马逊 SP-API 或 Shopify Admin API，Q-23 已确认；创建良仓售后出库单经积加，Q-25 已确认）；需要生产厂的在工厂工作台生成任务。人工操作清单只作兜底：接口重试用尽后发起人转交（R-AP-05），或某项动作暂无接口。动作与适配器的对应见 P18 动作映射。 |
| R-AP-05 | 自动执行失败后重试 3 次，相邻两次间隔依次为 1、5、15 分钟（例：10:52 失败 → 10:53、10:58、11:13 重试）；仍失败则状态「执行失败」，通知发起人，可重试或转为人工操作清单。 |
| R-AP-06 | 绑定回复在全部动作成功后自动发出；任一动作失败则回复不发出。 |
| R-AP-07 | 驳回必须填原因；发起人在批准前撤回，与驳回同样处理。按审批单来源分三种：① 售后负责人在 P08 确认时提交的：售后单退回「待确认」，售后负责人在 P08 修改后重新提交。② 坐席在收件箱提交的（路径 B）：售后单退回「待确认」并锁定给原发起人，坐席在工单上修改后重新提交，复用同一售后单号；P08 对这类单只读，提示「等坐席重新提交」。③ 系统发起的（生产厂报价后的快递费用报备、补充报备）：售后单保持进行中，当前环节「报备审批 · 待重新提交」，售后负责人在售后单详情修改金额后重新提交，或退回生产厂重新报价。 |
| R-AP-08 | 人工操作清单指派给发起人，4 个工作小时内回填；回填金额须与审批金额一致，不一致需填说明并由原审批人确认。 |

### 7.8 报备（R-FL）

| 编号 | 规则 |
|---|---|
| R-FL-01 | 报备只有两类：快递费用（由 FSH 承担或先垫付的寄件运费）；额外赔偿（FSH 向客户支付的现金，包括部分补偿、免退货退款）。 |
| R-FL-02 | 客户退回商品后的退货退款不是报备，按高风险动作审批。 |
| R-FL-03 | 与库存分支无关，只要 FSH 出钱就报备。默认无金额门槛（Q-10 默认值已设）。 |

### 7.9 售后责任、处理方式与承担比例（R-AS）

| 编号 | 规则 |
|---|---|
| R-AS-01 | 处理方式三选一：调整安装方式；寄配件（含换新、整机补发）；退款或部分补偿。 |
| R-AS-02 | 责任四选一。规则能判定的由规则判定，其余由 AI 建议，人工确认后生效： |

比例按三组费用分别记录（客户确认 Q-03）：产品成本、快递物流（运费）、其他费用（额外赔偿 + 其他）。

| 责任类型 | 判定依据 | 产品成本 FSH / 工厂 | 快递物流 | 其他费用 | 协商 |
|---|---|---|---|---|---|
| 客户使用问题（含顾客购买、使用不当） | 按指导调整后解决；照片显示误用；保修外自费购买配件 | 100 / 0 | 100 / 0 | 100 / 0 | 不适用 |
| 产品质量问题（抱怨索赔） | 保修期内失效且排查不成；照片与已知缺陷一致 | 0 / 100 | 0 / 100 | 0 / 100 | 需要 |
| 物流问题 | 轨迹停滞满 5 天且超预计送达；签收破损；错发漏发 | 100 / 0 | 100 / 0 | 100 / 0 | 不适用，FSH 向承运商或良仓索赔 |
| 其他（需填写理由） | 不属以上，例如物流损坏后双方分摊、责任不清 | 50 / 50 | 50 / 50 | 50 / 50 | 需要 |

台账与列表等紧凑表格在三组比例相同时写一个值（例「0 / 100」），不同时写「按费用项」并可展开；详情页与说明文字写「三组均 FSH 0 / 工厂 100」，三组不同时逐组列出；工厂承担金额 = 各组费用 × 该组工厂比例之和。

| 编号 | 规则 |
|---|---|
| R-AS-03 | 改判责任（与规则或 AI 建议不同）必须填理由，记入审计日志。 |
| R-AS-04 | 良仓库存在确认时经积加查询；创建售后出库单时库存已用尽 → 自动切到良仓无货分支，原报备作废，按生产厂报价重新报备，并通知售后负责人。 |
| R-AS-05 | 客户改地址：寄出前自动更新并通知良仓或生产厂；寄出后由售后负责人决定改派或补发。 |
| R-AS-06 | 协商最多 3 轮提案，第 3 轮后未达成一律待升级；任何一轮工厂还价后，售后负责人都可以直接升级。提案、还价、录入最终比例都按三组费用分别给比例。 |
| R-AS-07 | 已进入结算批次的售后单，比例不能再改。 |
